# 文档维护规范

本规范约束本仓库所有自有文档及生成模板。项目工程与数据保护要求见 [AGENTS](../../AGENTS.md)。文档只描述现行行为、必要操作和可核对的事实；实现与预期契约冲突时记录问题并确认行为，不用改文案掩盖失败。

## 命名与导航

普通目录和专题文件使用英文小写 kebab-case。目录入口保留 README.md；根 AGENTS.md、CONTRIBUTING.md、CHANGELOG.md、SECURITY.md 和 GitHub 模板保留约定名称。README.en.md 为英语入口。第三方许可证、NOTICE 与商标原文保持原名原文；插件 artifactName、源码目录和发行包名称属于产品契约，不按文档命名规则更改。

每份现役专题有一个明确职责和入口。docs/map.json 登记文档路径、主题 ID、唯一 authorityFor、现役 codePaths 和验证入口；不复制正文规则。新增或移动文档同时更新父索引、map、引用方、检查工具与生成模板。目录索引只提供阅读顺序和专题链接，不另立规则。

仓内链接使用相对路径和正斜线，大小写与 Git 路径完全一致；导航使用可点击链接。跨仓文档链接使用明确仓库 URL，不依赖个人相邻目录。当前指南链接 main 的现役入口，历史证据固定 commit/tag。路径迁移不保留无用途转发页；确有外部兼容用途时须登记用途与退出条件。

## 内容归属

| 类型 | 允许的正文 | 不应写入 |
|---|---|---|
| 根 README | 产品定位、最短开始路径、用户限制与入口 | 开发制度全集、接口字段全集 |
| AGENTS | 强制工程边界、授权、数据保护、任务入口 | 操作手册和版本工作总结 |
| CONTRIBUTING | 贡献者上手与提交入口 | 重复发布命令和协议规范 |
| 目录 README | 职责、阅读顺序、链接 | 独立业务规则 |
| 用户指南、随包 README | 操作、可见行为、限制与排错 | 内部实现、CI 设计、验证流水账 |
| 架构 | owner、依赖、不变量、生命周期及原因 | 页面像素清单、重复接口字段、发行步骤 |
| API 与协议 | 版本、输入输出、错误、生命周期、安全边界 | 项目任务清单、单次验收结果 |
| 作者指南 | 使用契约的方法、最小示例、生成和验证 | 另一份宿主契约 |
| 框架与项目适配 | 独有的配置、任务、日志及兼容边界 | 公共协议、公共事务全文 |
| 开发与发行 | 环境、命令、前置条件、输入输出、副作用与失败处理 | 缺陷台账和用户操作大全 |
| 测试 | 选择与运行方法、证据含义、未覆盖边界 | 手工抄写用例数量、某轮成功记录 |
| 状态台账 | 未解决问题、影响、缺失验证及完成条件 | 完成清单、永久制度、无完成条件的维护口号 |
| ADR | 背景、决定、理由、后果与有效状态 | 持续追加的现行 API 手册 |
| 更新日志 | 对应版本实际发布的变化 | 未发布工作和当前规范 |

一个规则只有一处完整定义，其他入口使用摘要与链接。Host 负责宿主公开 API、接受版本和运行语义；Plugins 负责作者流程、官方适配与插件发行。随包说明允许保留离线使用必需的提示，不能为去重破坏独立阅读。

## 格式与事实

自有文档使用 UTF-8、LF、文件末尾一个换行；普通文档一个 H1，标题层级连续。代码围栏标明语言，命令使用 text 或实际 shell。列表、表格和代码块前后留空行。API 字段、命令和路径使用代码格式，目录导航使用链接。模板及第三方原文按其用途豁免标题规则。

示例明确标注协议和用途；当前生产、Host 可接受范围、兼容样例和脚手架输出分别说明，不把旧版本全局替换成新数字。可机器核对的事实取自源码常量、注册表、schema、manifest 或测试策略；不在多个正文手工维护数量。示例由生成器产生时修生成源并验证生成一致性。

中文与英语指南保持事实、限制一致；精简翻译必须声明范围。上游发现注明核对日期与固定来源，发现发行、源码审读、受控测试和真实环境验证分开记录。NOT_RUN 不能表述为通过。

ADR 标明 accepted、partially-superseded 或 superseded，列出替代契约；历史事实不改写成当前版本。未完成事项按主要 owner 维护，跨仓只保留自身影响和链接，完成或失效后移出当前台账。

不写会话依赖、尝试过程、已放弃实现、已完成迁移清单或临时报告路径。临时材料放仓外；规则不能依赖本机父目录文件。

## 正文结构与审阅

同类文档采用一致的阅读顺序，不要求相同的标题数量。架构专题先说明职责和范围，再说明依赖、生命周期、不变量、失败处理及代码与验证入口；API 参考说明输入输出、错误、安全和示例；操作指南说明前置条件、步骤、结果及排错；项目适配只维护项目差异和证据边界。

标题必须有实际内容。没有正文或子节的标题属于空节，注释、空围栏和占位符不能代替内容；父标题可以直接包含有意义的子节。单一子节或重复文档标题的外层章节应检查是否可以合并。多主题长文按读者问题分节，短而单一主题的文档允许只有一级标题，不为满足模板填充空话。

同级标题描述同一层次的问题；新增规则归入对应主题，不在文末不断追加。长段按条件、动作和失败后果拆分，表格用于可比较信息，流程图用于时序或分支，不把完整接口字段表嵌入架构总览。

逐节审阅必要性、完整性、归属和事实来源。完整规则只维护一处，其他页保留必要摘要与链接；去重不能丢失身份校验、恢复前提、失败保护和离线使用条件。当前版本引用 manifest/源码或指定契约表，上游核对记录明确日期与固定来源，历史版本事实不自动改写为当前版本。

检查器校验本仓采用的 ATX 标题、围栏代码、行内代码和链接，不作为完整 CommonMark 渲染器；新增 Markdown 语法时先核对解析及回归覆盖。代码格式中的路径说明不作为导航自动检查，需要人工核对；可点击的源码定位链接可纳入路径检查。

检查器拒绝空叶子章节；长篇未分节、单一子节和重复长段仅产生人工审阅提示，不作为自动语义结论。提示经逐项审阅处理，不能以工具通过替代正文核对。

## 验证与交付

运行本仓文档检查和适用工具自测；双仓迁移同时用显式对端路径验证 main 文档链接。检查覆盖格式、路径、大小写、片段、map 和指定契约；人工审阅语义、权威归属及支持范围，工具成功不代表全部语义已证明。

随包 README 是发行输入。修改后按实际稳定 catalog、发行游标及包内字节核对版本，不能只因扩展名是 md 就忽略包内容变化。纯文档和不影响运行的本机治理不重复构建软件；涉及产品运行或发行内容的行为改变，执行相应构建与验收要求。

在仓库根执行 `node tools/check-doc-links.mjs --partner-root <对端仓库绝对路径>` 检查双仓现役链接；省略对端时明确记录跨仓 NOT_CHECKED。contract:versions 表格由检查器核对权威常量或兼容 JSON，正文仍需人工审阅。

`validationPaths` 指向实际检查入口或用例策略文件，不是保证该专题已通过测试的资格记录。历史 ADR 和 changelog 不按当前版本自动改写。

工具自测：先将进程级 `NEXUS_TEST_ARTIFACT_ROOT` 指向外部目录，再执行 `node --test tools/markdown-docs.test.mjs tools/governance.test.mjs`。源码快照大小写回归使用 `python -B tools/test_build_source.py`；其 fixture 不修改正式仓库 index。
