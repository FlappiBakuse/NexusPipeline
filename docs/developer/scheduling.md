# 持久调度、重试与完成动作

`ScheduleMinutePolicy` 使用保存的星期、本地分钟和时区选择当前分钟。
持久水位只前进；重复 tick、墙钟回拨及夏令时重复的同一本地分钟不能另造 occurrence。
停机错过的分钟不补跑。未知时区为该日程记录诊断并跳过，其他日程继续扫描。
`ScheduleOccurrenceStore` 在同一事务提交水位、分钟声明、occurrence 和 runId，成功后才能准入执行。
事务失败不推进水位，也不启动进程。
回滚日志的临时 `SQLITE_BUSY` 保留水位和原业务身份，调度在下次 tick 重试；其他 SQL 错误继续阻断准入。

资源暂时冲突时保留原 occurrence、runId、起始时间、deadline 和已消费预算。
排队元数据使用实际生命周期协调器登记，等待期间不占用执行文件及进程资源。
首次执行提升同一逻辑许可；永久失效的定义以持久 blocked 结论结束等待。
独占实例租约生成启动代次；`RunOnStartup` 默认关闭。
启动队列绑定代次与原队列身份，定义修订不能为同一次启动产生第二个 run。
冷启动保留旧事实，不凭新进程重建未测量的预算尾部或自动补跑等待项。

`IManualWorkHandler` 单独读取业务任务的修订、手动可用状态、时区、超时和通知选择，无日程任务不需要伪造周期计划。
同一 provider 可以同时实现手动接口和 `IScheduledWorkPlanningHandler`，注册桥保留两种能力。
手动回调使用 `ManualWorkInvocation` 的真实 Host 冻结身份及任务修订。
`WorkTasks.RunAsync` 绑定当前已鉴权 frontend write 的原 operationId 和 client，不接受插件指定 run、attempt 或日期；已受理任务独立于页面请求存续。
受理、回调开始与结果分别保存在不可变 source 和单一数据库索引中。重放原操作只返回其旧收据，即使任务随后被删除也不重新运行。
恢复必须证明原 creator 已停止；没有开始记录时收敛为 `notStarted`，已开始而中断时保留 `unknown`，不自动重放外部副作用。
`WorkTasks.QuiesceAsync` 从当前业务任务读取关联日程身份，阻止新回调并等待取消后的实际回调及全部 SDK root borrow 释放；调用方持有租约直到原子保存结束。
原 frontend 回调结束或取消时会退役其遗留租约，回调结束后的 SDK 调用不能沿用原权限。
`ReadCurrentAsync` 仅在实际受理回调内提供 frozen run、attempt、修订和 Host 本地日期、时区；`ReadClockAsync` 提供当前 Host 时钟供计划元数据使用，不能替代运行冻结日期。
同时实现手动与日程接口的 provider 为每个计划声明 `ownerTaskId`，Host 核对私有任务的关联日程、修订、时区、超时和通知选择，并冻结该任务快照。
同一业务任务的手动及关联日程回调共用排他入口；`ReadCurrentAsync.TaskId` 来自真实 owner 快照，`SubjectId` 仍保留原 invocation 主体。
`WorkTasks.ReadAsync` 每次读取至多 128 个真实任务，返回持久 source/begin/result 的最近 16 次事实；插件结果缓存不参与 Host 终态判断。
下一运行时间使用实际保存的公开计划、分钟水位与已受理本地 occurrence，处理夏令时跳过、重复分钟和时钟回拨。
`HasStoppedAsync` 仅供当前排他回调核对同 provider、同任务的确切旧 run/attempt；原始持久完成、真实进程停止或已被当前排他入口证明排空的同代旧回调才允许返回 true。未知身份及当前 writer 不能获得停止证明。

`WorkEffects` 仅在实际受理回调和当前秘密权限下提供持久副作用声明。
`BeginAsync` 先绑定实际任务秘密修订、Host 冻结日期和整项活动，`AcquireAsync` 再声明角色与服务器。
插件通过纯 `ProjectIdentity` 从实际秘密材料投影认证身份；Host 复用现有 DPAPI 保护的密钥计算 HMAC，不保存认证原文。
身份规则版本按插件与字段固定，改变版本需要明确迁移，不能借换版本避开去重。
同一认证身份在不同任务中共享声明；其他活跃 owner 返回 `Busy`，已停止但未确认的声明返回 `Unknown`。
活动完成且实际确认回调停止后，后续回调可开启新的协调轮次；已确认角色跨轮次保留，新增角色可独立声明。
未确认轮次不能重新开启；只读恢复遇到未记录角色时仅创建内存租约，获得正向确认前不增加持久角色记录。
只有 `New` 可以在外部写请求前持久记录 `SubmittedAsync`；重复提交和已确认后提交均拒绝。
`Unknown` 仅接受只读协议获得的正向确认；全部已记录角色确认后才允许 `CompleteAsync`。
租约属于原回调，返回、取消或更换凭据修订后不能继续使用。
同一回调的原子秘密文档写入先调用纯 `CanRotateIdentity`，并核对旧修订与前后身份一致；默认拒绝轮换连续性。
实际提交完成后，Host 保存与不可变秘密文档来源相连的轮换事实，再绑定原租约到新修订。
轮换核验失败即阻断后续副作用；读取原提交收据不能单独恢复提交权限。
两种纯投影回调期间禁止调用 Host 端口，输入和输出秘密草稿按调用销毁。

手动运行的通知使用原 `notificationOperationId`、冻结目标、真实 manual source 和 begin 记录。
普通 frontend 请求、另一运行或另一激活不能借用该来源；重放只返回原受理收据，修改正文或目标会拒绝。
手动与计划通知共享目标快照、秘密引用、投递队列及 Host drain 生命周期；队列受理不等于外部送达。
扇出与全部投递成员在一个数据库事务中提交，失败不留下部分受理；缺失或禁用目标单独记录。

扩展计划任务使用同一个分钟调度循环。只读计划包含任务身份、计划与任务修订、时区和有限通知选择，
实际回调必须通过 `ExecutePlannedAsync` 接收这两个原始修订。插件在业务副作用前原子核对保存修订；
私有任务内容变化必须推进任务修订。过期注册或另一激活不能继续使用旧调用。
同分钟短暂资源冲突释放后重新读取当前计划；已持久受理的 occurrence 去重，跨分钟不补跑。

计划回调与通知投递分别记录事实。通知来源绑定真实 occurrence、回调开始和保存的通知任务，
来源、全部投递成员及凭据引用在同一事务提交，不生成执行 attempt 收据。
通知队列在回调活动释放前完成生命周期交接；投递失败或 Unknown 不更改回调业务结果。
回调 Task 确认结束并持久记录结果后释放活动；失去旧宿主时，只有真实原生身份已停止才能记录 Unknown。
冷恢复不重建单调计时，不重放回调；墙钟回拨保留实际观测时间及其质量标记。
同一个 `PersistentScheduleService` 对象只拥有一次宿主生命周期，停止后再次启动会明确拒绝。

普通失败和中断恢复使用不同的资格判定。正常运行时，冻结的单绑定 `MaximumAttempts` 限制实际调用总数；
已退出的 provider worker 在完整停止和收集后仍没有有效终态时，当前 attempt 记为 Interrupted，保留缺失终态与原生退出事实；
Host 和重试扫描器继续运行。配置还原完成后仍须通过原冻结的安全声明、宿主批准与预算核验才能产生后继；普通进程退出不使用此分类。
已明确收集为普通失败、前次全部 writer 已停止且该绑定配置已还原后，才在同一逻辑步骤生成新的 invocation。
成功的前序绑定不重跑；当前绑定完成有限调用后继续后续绑定。取消、Unknown、致命总超时和恢复未确认均不新增调用。
普通失败沿用保存的业务重试次数，无需把脚本声明为可在中断后安全重放。
每次调用使用独立实际 Job、配置会话及原始输出身份；`runId`、父 attempt、冻结候选和步骤业务键保持原值。
内部 invocation 只记录实际发生的调用，SDK 的 attempt 身份与序号仍表示原始受理或中断后的后继。

`RetryAuthorityPolicy` 只授权中断后的安全后继，同时冻结 provider 的完整 worker 安全声明和宿主批准。
宿主自动中断重试默认关闭；普通脚本可执行不等于副作用安全。
声明必须覆盖实际执行表面、稳定业务身份及中断语义；未知副作用或无法证明预算连续性时拒绝自动后继。
Host 收到 ApplicationStopping 时同步停止重试扫描，避免执行消费者退出后仍受理新的后继。
未进入 effect gate 且已证明无副作用的中断记录保持 Blocked；恢复历史不得伪造单调计时终点。
后继使用新的 attemptId、操作和 Job，保留原 runId、步骤业务幂等键及全部旧收据。
原绑定的调用上限累计此前所有父 attempt 内实际 invocation，不能通过中断另取一份额度。
真实 writer 停止、配置还原、无隔离、预算和再次准入均满足后才允许中断恢复。
持久总预算、回退等待和 deadline 共用；时钟回拨、资源等待及重启不能延长额度。

冷恢复的新 attempt 沿用原始候选与发布游标，在新的 before 现场核验保存修订。同一 attempt 内的普通 invocation 使用上一调用已封存有效活动输出；绑定授权和任务意图保持冻结。
`initialPublicationRevision` 是当前运行状态格式的必需字段。
前置钩子仅按保存的 `PreOnceAfterSuccess` 选择重复或继承；继承绑定实际成功结果、原始输出和停止证据。
`PostFinalOnly` 只在确有下一次普通调用额度、主调用已明确失败且恢复条件可证明时延后后置钩子；否则执行当前调用的后置钩子。
失败的前置钩子阻断本次主调用及后置钩子，但仍消耗一次已配置调用；失败的后置钩子保留实际主业务事实，按剩余额度处理。
单绑定总超时跨普通 invocation 共用，不能因再次调用重置；无输出超时按每次实际调用重新观测。

完成动作冻结队列修订、动作、原收据及真实启动来源。
同一关闭组不能混合不兼容动作，各成员仍保留自己的不可变身份。
只有 Completed 且配置恢复为 Restored 或 NotRequired 的收据可以成为候选；业务失败不会改写这些事实。准备期 Selection 或运行期 BindingSkip 的依赖跳过均排除完成候选。
协调器先登记已接受队列，再进入 drain 阻断新准入；原有工作必须持久结束后才能执行动作。
关机、休眠、重启使用可取消的真实单调 60 秒倒计时，退出使用正常宿主退出请求。

本机授权绑定真实来源、主体、队列修订、动作及每个收据，不能由调用方自报本地主体来借用。
本地设置或修改非 None 动作要求 CompletionLocal；远程同动作普通编辑及撤销动作保留普通写权限。
真实本地手动起点或持久 scheduled/startup 来源在候选合格后建立一次动作使用权，无终态确认弹窗。
远程/MCP 手动运行不能继承本地起点；重试沿原始来源追溯。权限使用期从候选授权开始计时。
许可使用与撤销受同一授权 owner 协调，效果进入前再次检查恢复、资源和来源。
进入效果的持久记录提交失败时不能调用系统端口；未知系统结果保留事实，启动后不自动重放。
测试只使用受控电源端口及原生符号绑定核验，不执行真实关机、重启或休眠。
Web、CLI、MCP 的能力和来源限制由公共控制面接入。

运行天数由同一调度循环维护本机日期水位。新 Host 当天只登记水位，持续运行跨日时仅递减一次正数；墙钟回拨、同日重复 tick、重启和离线漏过多日都不会补扣。general 同步开启时仅递减用户覆盖，原始绑定保持原值；其他用户递减各原始绑定。定义修订与日水位在同一事务提交，执行占用定义时稍后再处理。
每日成功上限读取 `execution_binding_successes` 中按逻辑 run/binding 去重的成功事实，以本机日界划分。失败和未知结果不消耗成功额度；历史记录清理不移除额度事实。计划准备及实际分派前分别核对。

宿主报告 ready 前，由现有调度 owner 完成首轮运行天数、启动队列及分钟元数据提交，避免首次设置或定义保存与初始资源租约竞争。后续 tick 及实际任务仍使用同一后台循环；失败继续通过原有调度故障状态公开。

## 无变化扫描与通知收尾

重试和日程 owner 各保留最多 64 项候选，相关业务库提交后失效，重启重建。
实际受理重新核对权限、定义、预算、资源及持久事实。空分钟只更新进程内扫描边界，不创建分钟文档或推进持久水位。
队列或 provider 确有当前分钟到期任务才提交分钟归属，provider 使用保存的观察时刻重新生成 occurrence。
显式分钟提交保留原请求重放；时钟回拨、过期、重启和启动日程继续服从原语义。

通知启动只协调缺失终结注册和实际待办；来源在消费时核验，已终结来源不参与空队列历史重放。
通知队列空闲时等待登记完成事件，实际受理唤醒 worker；活动投递继续按有界批次处理，停止会取消等待。
缺失登记每轮最多补齐 64 条，保留待办队列拥有权，停止时按条取消；补齐后停止登记扫描。
投影、展开与投递批次为实际来源借用 `NotificationAttemptReads`，复用受保护终态 journal、计划及定义。
跨网络等待保留 owner，批次结束、取消或实例关闭释放；最多 64 个 owner，超容量继续普通校验。
投递状态、来源 SQL、秘密、权限和 Unknown 副作用逐次核对，通知引用读取当前不可变来源与路由投影。
终态回执、历史目录、通知登记及实际发送各有自己的完成事实。验收分别等待原来源登记、全部路由展开、
投递终态和目标回环接收；终态落盘后的进程中断由冷启动补齐缺失投影及通知，已提交投递返回原结果，未知发送保持原隔离。

验收覆盖无任务跨分钟零提交、真实到期、外部提交、不同通知来源隔离、终态旧字节锁定、取消、重启及原回执重放。
每轮队列核对完整日志与逐目标通知，保留未知发送状态，不依据性能目标重复外部副作用。
