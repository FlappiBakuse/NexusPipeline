# SQLite 状态存储

`Platform.Storage.Sqlite` 拥有 SQL 和数据库连接，Core 用例通过类型化端口提交领域事实。
数据库保存格式、schema 版本、实例 ID 和 SQL 契约摘要。仅当前首发 catalog 与 digest 可准入；旧开发期及未知布局只读拒绝，原数据库、WAL、SHM 和 journal 保留。实例 owner 的独占租约仍保护当前读索引维护与恢复。
初始化只接受已确认的新实例，数据库丢失不会触发重建空库。
连接使用 WAL、FULL、foreign keys 和有限 busy 等待。
每个数据库对象最多容纳 64 个已执行或等待写请求，串行等待上限为 2 秒。

## 启动与恢复准入

普通启动使用 `StateDatabase.OpenCurrent`，在实例租约内验证初始化 guard、实例、格式和精确 catalog，补齐已登记的派生读取索引。恢复验证活动候选及其绑定；完成历史由对应访问和显式诊断读取。

显式完整诊断和维护准入冻结完整 DB/WAL/SHM/rollback-journal 文件组，在隔离副本上识别。
先验证 WAL 版本、页大小、帧边界、salt 和校验链，再检查 schema、实例、完整性和外键。
非空 rollback journal、撕裂数据或未知结构均保全阻断，不在原文件组上试修复。
WAL 复用仅接受 salt 能证明的旧代际尾部；旧尾部不能授权当前提交。
文件格式依据 [SQLite WAL 格式](https://www.sqlite.org/fileformat2.html#wal_file_format)。

普通恢复预检核对当前候选的 SQL 登记、物理 journal、typed plan 和 workspace 绑定。显式完整诊断另核对全部完成历史。
所有 owner 完成只读准备后才能执行恢复；准备期间索引修订改变会使整批准备失效。
核验完成后发布不可变 `RecoveryIndex`，执行准入只读该快照。
未知输入、未确认停止的 writer 或缺失权威根会阻断准入。
活动恢复批次保留 10000 项容量边界；已绑定历史使用点查或同家族读取。完整诊断按主键分页验证完成历史。

持久受理事务同时预留恢复生命周期的剩余容量：最多 10000 个 journal、65536 条文件 effects、10000 条 Job 成员记录。
Job 按 journal 成员行计数；同一物理 Job 关联父执行与配置子 journal 时分别计入。
执行根据冻结计划的调用次数、配置槽及现有 Job 上界预留；配置子 journal 使用父预算，更新预留正向和反向 effects。
实际插入通过同一数据库事务消费预留；新受理同时计入活动家族已有行和未用预留，容量不足时以 `recovery_capacity_exceeded` 拒绝，
不能抢占已受理任务的配置恢复、停止收据或回滚余量。请求重放返回原受理，不重复扣除。
普通 owner 的全部成员提交后释放未用余量；完全结束且没有 pending effect 的家族不再消耗活动额度，历史行继续保留并校验。
宿主维护保留最多三个 Job 成员的额度，允许候选失败后重新启动原 Host；只有维护完成、家族全部提交且原有原生观测证明全部 writer 停止，冷启动才释放余量，不能在文件回滚提交时提前释放。
普通启动核对活动家族的成员、计数及冻结计划推导的原始预算；显式完整诊断在隔离副本验证完整库存。预算篡改或未知 schema 保持拒绝。
这些是同时活动恢复工作的有限容量；完成历史不再受同一总量上限限制，但不承诺无限磁盘或固定启动耗时。达到活动上限不删除恢复证据，也不把已受理工作改判为未知格式。公开完整诊断快照仍有限，生产历史读取不依赖它。

接受事务登记真实 creator 的 PID、内核创建时间、映像路径/摘要、SID、提升状态和会话。
writer Job 在首个进程执行前登记；仅在 creator 已停止后打开其 Job 查询，避免延长 kill-on-close 句柄寿命。
PID 复用、查询失败、跨会话不可见、缺失记录或 Job 名称消失均不能单独证明停止。
恢复者持有实例独占租约，并在首次写入前登记自己的身份。
副作用检查只排除当前恢复者；较早中断的恢复者仍须证明停止。

## 操作与不可变证据

同一不可变 blob 的并发读取在首次摘要核验后共享一个私有只读句柄；Windows 句柄持续拒绝写入和删除，后续 reader 仍核对实际文件身份、长度与完整引用。最后一个 reader 关闭即释放证明，重新打开必须重新核验摘要。它不缓存可变 SQL、进程状态或已经释放的文件。

游戏根进程按独立 target/Job 保存。重试产生新的调用和根进程，保留前次停止证据；调用日志限制每轮启动范围，不以整个 journal 的 step 唯一约束阻断合法重启。当前读索引维护仍要求实例租约和启动准入，旧或未知数据库保持只读拒绝。

`operations` 的 operationId 同时绑定主体、请求摘要和种类。
相同请求返回原接受事实；不同主体、摘要或种类的冲突不泄漏原请求。
compound 接受事务一起登记 operation、journal、隔离和 pending file outbox。
SQL 成功仅表示接受事实，不能解释为文件效果已经完成。

`JournalStore` 为 `nexus.execution.journal`/1 的每个 revision 独占创建并刷盘独立文件。
读写使用按 runtime 物理身份及 journal ID 命名的当前用户内核互斥量，等待上限为 30 秒。
锁遗弃后仍须核验完整历史；缺口、半写、非法阶段边、身份或计划变化保持拒绝。
物理收据领先 SQL 时，只能逐修订向前投影，不能重做已完成副作用。
终态后的清理使用独立收据，不能回退原业务事实。

固定 schema 的成功校验与日志相邻文本的成功关系各保留至多 8192 项 SHA256/长度证明。
解析图缓存仍限 128 份、原文总计 1 MiB；摘要证明不保存 JSON 图或文件、SQL、进程状态。
活动 attempt 的读取复用其持续只读保护的计划及 journal 前缀，并读取新修订；无保护、容量超限或保护结束后重新计算当前字节摘要。当前 SQL、计划绑定和实际效果准入继续核对。
文本证明采用 SHA256 抗碰撞假设；淘汰或字节变化后重新完整校验，不能授权文件存在或副作用。

`runAttempt`、`updateApply` 和 `extensionApply` 使用持久效果门禁。
门禁只能进入一次，或永久封闭尚未进入的入口；同一 SQL 写事务裁决竞争。
门禁只证明是否曾授权开始，不能代替现场、writer 或文件收据。
prepared/revision 1 的登记缺少物理 journal 时，只有 typed plan、完整前态、pending outbox 和停止证据齐全，
才能独占创建初始证据并终结为 notExecuted；未知占位、工作区或撕裂文件不能填补。

## 冻结计划与配置

`nexus.execution.plan`/1 冻结定义内容、源修订、根映射、物理映像和 runtime 文件、任务顺序、预算及重试权威。
读取器核对实际定义关系和启动字段，不信任调用方复制的路径或安全性声明。
准备对象持有真实输入租约；外部编辑、同字节物理替换或 runtime 文件变化不能沿用旧权威。
资源键保守覆盖卷级路径关系与硬链接；执行、编辑、删除和维护共用协调域。

`nexus.execution.run-attempt-plan`/1 为本次尝试绑定独立配置计划、日志前态和输出目录。
执行、取消和恢复共用同一 attempt owner；迟到输出不能改变其他尝试。
已运行的中断尝试保留 Interrupted 及真实恢复事实，不能重置为 Waiting。
只有冻结 safe、宿主批准、writer 已停、无隔离及原预算/deadline 均满足，才允许持久 retryWaiting。
新尝试换 attemptId，保留 runId 和业务幂等身份；未知安全性不会自动重跑。

`FileTreeArchive` 区分缺失、文件和目录，按不可变摘要保存准确字节。
重建只创建新目标，不覆盖未知现场；Windows 卷序列号与文件 ID 区分物理对象。
相同摘要不能代替相同物理身份，定义依据 [FILE_ID_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info)。
配置修订、编辑、差异回写和交换由 Configuration owner 处理。
每个文件副作用引用自己的冻结 planPath/planDigest，不能借用总执行计划。
跨卷先建立可验证备份和同卷候选，再以禁止覆盖的移动安装、退役和还原对象。
配置还原不修改用户当前保存的快照；未知字节、物理形态或未停 writer 保全隔离。
详细规则见[配置](configuration.md)与[执行](execution.md)。

载荷 plan 冻结 updateApply/extensionApply 的动作、目标根、前态、候选、原物理对象及资源。
冻结不授予执行权，也不代替包信任、扩展退役或 writer 停止检查。
宿主更新与扩展安装分别由 Maintenance 与 Extensions owner 提供；扩展的持久源、物理载荷和最终提交见[扩展](extensions.md)。

## 历史、日志与图片

`attempt_receipts` 不可变追加每次尝试的四维事实和原计划、来源收据摘要。
run 的最终历史独立投影，不覆盖旧 attempt；相同尝试仅接受完全相同的重放。
恢复时无法得知的耗时或结束时间使用明确质量标识，不编造测量值。

记录按结束时间、runId 升序使用稳定 keyset 游标，默认 50、最多 200 项。
自动化、账号、业务结果和 UTC 结束时间区间共用产品 SQL；区间包含起点、不包含终点。
对应有序索引与参数化条件提供分页，容量诊断使用实际分页 SQL 记录查询计划。
记录和图片元数据读取不打开原始大文件；返回前释放 reader，不长期占用 WAL 快照。
数据库 checkpoint 分别报告 busy、WAL 帧数和已收敛帧数。

日志目录绑定原 attempt、角色、artifact 摘要和完整性，不从当前文件重新推导旧事实。
按有界分段流读取原始输出；慢订阅使用有界队列和 gap 事实，不阻塞原 producer。
截图沿原 main writer 的嵌套家族记录 source、root、停止和 collected 证据。
完整 PNG 原字节独立保存，不能挤入原日志预算或用重新编码图替代原图。
图片目录按 attempt 和位置分页，保存每帧独立 capture 身份、真实尺寸、原摘要及 Captured/Unavailable 事实；同一步的多张原图分别可读。
未知尺寸保持空值；元数据不授予新的截图或设备控制权。
最终记录、截图资产关系和原 producer 标记在同一 SQL 事务投影。

资产关系在持有已验证原文件句柄时提交，拒绝缺失、损坏、跨实例或无关系的内容。
同一摘要按 run 和用途建立引用，游标包含摘要及用途。
打开原内容重新核对关系、摘要和物理文件，流的寿命持有原文件句柄。

## 内容退役与精确清理

日志和图片退役由 `ContentRetirementService` 建立精确、不可变的 family/content 证明，
并通过既有 `fileCleanup` journal/outbox 接受清理。
元数据、原四维事实、原图摘要与 producer 身份保留，后续内容读取返回明确 Retired。
图片退役按内容 SHA 而非帧身份选择；多帧引用同一 PNG 时共享同一退役状态和清理证明。退役不是物理删除回执；原 PNG 或日志仍可能因共享引用、打开的流或清理隔离保留。
活动执行、待恢复引用、通知 Queued/Sending/Unknown 及其他 owner 的关系均保护内容。
operationId 重放只能返回原清理身份，不能创建新的删除授权。

`nexus.file.cleanup-plan`/1 仅接受本实例规范内容路径、大小、摘要和父目录/对象身份。
清理逐对象核验，不递归删除；持有原生 DELETE 保护句柄期间重新核对全部识别的传递引用。
新引用取消待删项；未知 owner、版本、计划或权威根缺失会拒绝回收。
删除完成收据与 SQL outbox 分开对账；缺少完成证据的中断保持隔离，不能猜测已经删除。
prepared 无效果恢复要求完整前态，终结为 NotExecuted；它不冒充删除成功。
同摘要的其他 run、资产用途或配置/秘密引用继续保留原内容。

精确 journal 主键读取和单次操作内的有界 family 上下文减少重复解析。
局部上下文不跨调用授权，不能隐藏后续 SQL、物理身份、全局登记或证明的变化。
原始证据未知时保全，任何缓存都不能绕过最终准入与删除检查。
单次同步 Android 证据读取可拥有一个只读 autocommit 连接，查询结束即释放 command/reader；不缓存 SQL 事实或保持跨查询事务。
连接由实际数据库目录和文件句柄约束，作用域结束即关闭；下一次查询重新读取当前命令根。
图片目录与退役候选的元数据路径不返回可执行 prepared scope；真正发布与删除仍调用完整核验。

## 秘密、设置与备份

秘密由当前用户 DPAPI 保护的独立文件保存，SQL 仅引用经过验证的密文身份。
保存、替换与撤销有独立操作事实；普通 DTO、事件、日志和 doctor 不包含明文。
宿主系统登记意图与设置修订原子接受，外部登记结果独立核对，不伪装成文件 journal。
恢复只查询未知外部效果，不自动重放；未闭合意图保留类型化隔离。
见[秘密](secrets.md)和[设置](settings.md)。

数据库快照使用 SQLite backup API，目标独占创建，不复制在线单个 DB 冒充一致备份。
数据库快照与包含 blobs、journals、实例身份和秘密材料的完整实例备份有不同范围。
复制后的物理文件身份、跨用户 DPAPI 与未完成操作不能凭字节相同自动重绑定。
存储原生测试通过 `tooling/nexus.py test --group storage` 运行，实例、依赖、诊断和报告全部由外部 Temp runner 提供。

运行实例只接受当前首发 SQL catalog 与 digest；开发期或未知 catalog 只读拒绝。诊断副本核验与源数据库/WAL/SHM/journal 的原字节保护保留，不运行旧布局迁移；需要新实例时选择新的空目录，已有目录保持原样。

### 账号历史

run_records 保留唯一运行身份与全局最终事实。account_run_records 在同一终态事务中按冻结步骤的 userId 发布账号结果；
account_history 将该结果与同一运行的时间、恢复和退役状态关联。账号筛选与账号分组消费此投影，不推断当前绑定或同名账号。
单账号脚本启动的运行摘要也记录冻结账号；多账号仍保留运行聚合，通过账号投影访问各自结果。
账号范围内显示的运行时间属于同一持久运行区间。

历史账号页按结束时间、runId 升序查询；游标使用严格大于最后一行的二元组，跨页与同时间记录保持一致。
详情使用冻结账号名称及 stepIds 过滤任务、日志和图片。持久 attempt 与内部进程调用分别展示，图片调用序号从真实 capture writer 绑定取得。
日志描述、tail、原文件及 part 接受 invocationOrdinal，过滤同一持久 attempt 中的真实调用；省略时读取整个步骤的聚合日志。

## 受保护读取与连接复用

同步读取作用域最多保留 64 个目录句柄和 128 个 blob 只读保护。
目录句柄拒绝共享删除，每次仍读取当前属性和 reparse 标记；叶文件以不跟随 reparse 的句柄打开，核对身份、长度和引用。
持续保护内复用摘要，淘汰或退出后重新读取。文件树借用同一只读保护并重查库存、身份、单链接及长度。
实例身份在同步发布期间持续保护，嵌套读取借用同一实例及目录保护，结束时释放本次拥有权。

### 数据库连接与变化

实例租约最多同时复用四个数据库连接，读写使用各自的连接身份；每个连接的 SQLite 建议页缓存为 16 MiB。
写事务保持 WAL、FULL、外键和完整回滚，独立只读连接禁止写入。实例退出清空池并释放数据库文件保护，
无实例 owner 的局部池随作用域清空；超容量连接采用普通打开与关闭策略。
数据库文件及每级祖先在租约期禁止删除，取得保护时完整核验路径与物理身份；后续从同一文件句柄核对身份。
保护释放后的独立读取重新核验路径。command、reader 和事务及时释放，不在异步等待间保留读取快照。

同一数据库的嵌套同步历史读取借用外层连接和快照；正在执行 SQL 回调时，内层查询独立读取。
每个历史作用域最多保存 32 个已校验恢复快照，连续只读连接的 `data_version` 改变即清空。
不同数据库与连接分别初始化，禁止跨连接比较 `data_version` 或复用验证结论。
只有实际行变更或 schema 版本变化的已提交写入才推进后台库存失效；只读事务和无效果重放保持现有库存有效。
运行配置 owner、parent、活动会话及 journal 计划引用查询使用登记的派生索引，正常准入补齐索引，业务格式保持原值。

每实例发布队列按需拥有一条后台线程，空闲等待事件，最多 64 项；逐调用上下文隔离，关闭后排空并释放资源。

### 不可变证据与历史

不超过 64 KiB 的作业关闭证明、步骤证据和原始输出清单，在同一私有 blob 保护内复用不可变解码结果。
每文件保存一个类型，全局按原字节八倍加对象开销计量，最多 8 MiB；容量不足或较大文件完整读取。
每次打开仍核对物理身份、长度、完整引用、调用绑定及实例，最后一个保护释放即清除结果。
当前 SQL、进程、权限及实际副作用继续按实时事实核对。

单个父 journal 的保护最多 256 修订、16 MiB；切换父级、退出或超限后按普通路径读取。
首次保护解析已锁定修订，核对连续库存、实例、阶段、后继与计划摘要；每次检查新增目录项及 SQL 绑定。
活动 attempt 的原始修订、重试及任务投影复用由[执行读取](execution.md#活动执行读取)拥有，
配置快照及输出封存由[配置存储](configuration-storage.md)拥有，映像证明见[进程拥有权](process-ownership.md)。

不可变文本缓存最多 1024 份、原字节 4 MiB，仅复用与当前字节一致的解析，不保存权限或恢复授权。
契约 schema 图惰性初始化，静态引用解析后可并行求值，动态及未解析引用继续独占，禁止联网补齐。
严格 JSON、重复字段、大小及首次格式校验继续执行，成功摘要集合保留 8192 项上限。

## 回收引用读取

`BlobReferenceIndex` 按真实 owner 和当前候选建立传递引用，未知内容继续保全。
已完成 attempt 的引用按计划摘要、修订及规范资源声明摘要复用；已提交配置交换及编辑使用同一有界事实缓存。
每实例最多 8192 个 owner、65536 个引用及 32 MiB 计量缓存；登记变化、内容退役或淘汰后重新核验原计划、输出和停止证明。
未完成 owner 使用实时完整证据。通知读取不可变来源及当前路由/投递投影，日志目录核对当前登记、执行来源和最终回执。

无截图运行时输入的已提交 attempt，由 `CommittedAttemptJournal` 在同一事务核对登记、资源、已完成操作和最终回执。
回执文档摘要绑定实际终态字节，目录仍检查连续修订库存、计划及实例身份。
含截图运行时输入的计划共用完整历史保护，保留原始追加、重试继承及 source/root/collected 时序验证。
独立历史访问及恢复核验完整修订链；缺失终态、目录、未知库存、摘要或 SQL 回执冲突均拒绝回收。

归档预检先检查当前直接引用，历史遍历按候选批次保存 journal 游标和已找到的引用；通知引用在同批只遍历一次。
每页最多收集 16 个来源、256 个候选，预算耗尽后续作，暂停不创建清理操作或删除回执。
每次遍历批量读取现行内容退役关系；预检仅作性能提示，最终受理及删除在原生 DELETE 保护内重新核对完整引用。
单候选在同一保护内共享本次 `BlobCleanup`；释放、中断或新引用发布后重新判定，不跨保护沿用删除授权。
候选 reader 随本次检查释放；无效果冷恢复核对原对象与回执后取消，不为取消遍历历史引用。
预检冷却、执行/通知期间暂停及旧工作树中断续做见[扩展生命周期](extensions.md)。

历史到期候选通过 `julianday(created_at)` 的登记派生索引定位，保持时区和截止语义，无候选时跳过历史 join。
派生索引只接受登记定义，未知或改写索引拒绝。全库历史容量见[启动与容量](startup-and-capacity.md)，
回收验收覆盖共享引用、待通知、分页中断及原回执重放。
