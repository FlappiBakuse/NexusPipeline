# 执行计划与准入

旧 writer 的 PID 被查询权限受限的新进程复用时，停止观察仅在有界的内核进程快照证明创建时间不同后判为旧身份已退出。
快照布局先与当前进程句柄的创建时间核对；查询失败、记录缺失或同一创建时间仍为未知，不取得新进程的控制权限。

冷启动先核验原执行 owner 已退出。普通 worker 执行及其配置组缺少完整停止或输出收据时，只冻结派发并隔离相关资源，状态和诊断入口仍可访问；不采样未核验的可写现场、不补造闭合收据或重放脚本。目标、provider、hooks、捕获、预览及其他操作保留完整 writer 停止准入。

`ExecutionSelectionPolicy` 统一展开绑定、脚本、脚本账号和显式队列。
脚本按全局账号顺序与规范身份排序；队列保留显式成员顺序。
禁用项保留独立 skipped 原因，不因同一账号或脚本存在其他绑定而扩大直接目标。
无可运行目标和输入阻断分别返回原因。

`ExecutionPlanBuilder` 从实际定义、宿主设置、已保存配置及本机输入生成只读解释。
Generic 配置地址由声明的根身份和相对路径确定，不能从当前外部现场猜测或自动采用配置。
预检核验保存内容、契约、账号和脚本归属，以及现有运行组的 32 项配置资源预算。
专项入口要求已核验且当前已发布的 provider activation；未登记或已撤销的入口保持阻断。

dry-run 不接受操作，不写定义、计划或交换现场。
实际准备复用同一 builder，并再次比较定义、设置及保存配置修订。
总计划冻结账号顺序、逐项选择、真实镜像与目录身份、命令、资源声明及配置 slots。
每个 slot 绑定步骤、配置地址、目标路径和源修订。
父 attempt 持有独立配置交换计划、原始日志快照及自身输出目录声明。
历史读取只验证冻结引用与路径语法，不查询当前脚本目录的物理状态，也不重开当前执行镜像或重新执行计划。
新计划预检、冻结及 attempt 准备仍取得实际输入租约，核对当前根目录、父目录和镜像的身份、reparse 标记、大小与摘要。

配置受信任宿主截图运行时的总计划共享冻结 `captureRuntime`，保存 broker 镜像、完整运行时文件及各自物理身份、大小和摘要。
这些文件在准入前进入物理 Reference 声明，并由原执行输入租约持有。默认每步 1 张、PNG 至多 8 MiB、助手期限 5 秒；显式受信 PC 批次每步 2–200 帧、每帧至多 8 MiB、总 PNG 至多 64 MiB、同一助手期限 30 秒。单个 attempt 的受支持截图步骤数乘批次帧数不得超过现役 4096 条图片目录容量；Android 仍为单帧。
缺少该字段表示计划没有截图助手输入；历史元数据校验不重新选择当前 Host 镜像。

PC 截图从原目标阶段取得当前窗口的只读许可，辅助进程在原主进程 Job 内嵌套拥有。
source 保存原窗口、目标阶段与冻结 broker；root 在辅助进程恢复运行前保存完整原生身份。
辅助进程族先停止，再取得原主进程的完整停止闭包，最后发布 collected 与原 PNG 引用。批次逐帧验证窗口和进程身份，同步重绘当前窗口后拍摄并顺序写入原图；取消、截断或任一帧失败均不发布成功批次。
截图期限同时受原总预算和宿主停止信号约束；失败记录不可用，不改变原业务结果。
禁用宿主启动的目标可独立观察现有窗口，但原 Skipped 就绪列表、目标所有权与清理权限保持原意。
原主进程缺少必要停止闭包时，重启准入拒绝写恢复；已有完整闭包时可保存不可用结果，或对账已写入的原截图。
恢复不重新拍摄，也不把无法证明的辅助进程族伪装为空族。

`ImageCatalogProjection` 为每个已提交 attempt 独立保存 SQL 图片目录，重试保留旧 attempt。
`ExecutionRecordProjection` 仍独占最终记录发布；截图资产关系与派生完成标记在同一 SQL 事务中提交。
普通图片分页、启动库存和最终附件投影只核对原元数据，不读取 PNG。
显式原图读取仍须验证原 source/root/collected、已投影日志前缀、停止闭包、PNG 摘要和尺寸。
通知从最终记录已发布的资产关系取得原图引用；通知失败不改任务事实。
Generic ADB 使用原 Android 目标 owner 签发的 startup/step 绑定和原冻结工具，
只运行固定 `-s <endpoint> exec-out screencap -p`；stdin 关闭，不从 PATH 或当前环境选择工具。
二进制 stdout 独立受 8 MiB 上限约束，保留原 RGB/RGBA PNG 与 alpha。
自然根退出和 stdout/stderr EOF 必须发生在 Stop 之前；仅归属本次家族的 ADB 子进程参与停止，不接管预先存在的 server。
PNG 验证核对 CRC、chunk 次序、像素预算、解压扫描行及唯一完整 zlib 成员，拒绝尾随压缩数据。
未知图像尺寸保持空值，缺失或不完整输出只产生 Unavailable。
Android 目标自身的命令 collected 收据独立于截图停止证据；未闭合的控制状态仍阻断恢复或隔离资源。
完整停止证据只允许对账原图，不重拍；存活的旧 creator 或恢复者均阻止新启动接管。
日志/图片退役保留原目录、摘要与 producer 身份，内容删除沿既有精确清理 outbox 执行，见[状态存储](storage.md)。
MuMu 使用显式冻结的 manager/adb 配对工具和已保存的发现映射，依次执行截图前映射检查、二进制抓图、截图后映射检查。
三条实际命令均属于原截图 family，各自在恢复运行前登记原生身份；原端点、实例和映射变化使本次结果不可用。
三条命令及停止闭包共同受原 5 秒截图期限约束，原 RGB/RGBA PNG 不重新编码。
普通图片查询只核验计划结构、登记、原 journal 与当前 SQL 命令根，不读取执行时映射正文或配置快照正文。
显式原图读取、截图发布、执行和恢复仍要求完整输入证据；元数据读取不能签发执行许可。
实际 creator 在命令根登记后退出时，恢复保全未完成现场；完整 collected 后仅对账同一张原图。
尚未完成的范围见[当前范围](../status.md)。

Core 的 `AdmissionCoordinator` 先重放已接受操作，再获取共享 `ResourceLeaseManager` 的完整资源预留。
扫描、内容准备、输入核验和持久提交都在该管理器的短锁外进行。
独立目标可并行准备；同资源冲突、关闭过程或未知恢复索引会阻断新预留。

`ExecutionAdmissionService` 组合真实准备器、事务受理和运行 inbox。
同一 inbox 绑定一个实际实例、资源管理器和恢复索引。
有界单消费者队列统一执行二次重放检查、SQL 接受、初始 journal 物化、隔离发布及所有权交接。
消费回调不持有资源管理器或队列锁。
每项发布独立捕获并恢复调用方的执行上下文；排空任务不继承首项请求，显式抑制上下文流的调用使用空上下文，回调修改不流入其他项。
待执行集合另有 64 项上限，未发布的容量预留也计入此上限。
持久接受前预留 inbox 容量，交接消费该预留；受理失败释放预留，取走已接受所有权时释放待执行槽位。
满载不改变既有操作的幂等重放结果。

首次 builder 准备前捕获单调时间戳，`ExecutionTimeBudget` 随 draft 和 prepared 所有权交接。
配置准备和提交排队计入同一预算；冻结的持久 deadline 可缩短剩余时间，墙钟回拨不能延长已观察的窗口。
Core 预算快照向上取整到毫秒，可用已消费值重建窗口；它不表示实际进程运行时长。
持久 run 预算保存已消费时间、原始 deadline 及终态收据绑定；调度等待和重试继续消耗同一个窗口。

新 `execution.start` 只能从 builder 的 opaque draft 受理。
同一 SQL 事务比较 catalog、settings、配置修订、binding 修订与归属、契约、完整 manifest 引用及资产关系。
重放先核对主体和类型化请求摘要，返回原始引用，不重新读取当前定义或镜像。
调用方只收到回执；inbox 持有真实输入租约和配置子借用，交由运行 owner 消费。

SQL 失败不消费操作。接受后的失败先将恢复索引设为未知，再核对持久现场。
仅已停止、未进入效果且完整证明无效果的 attempt 可提交 notExecuted 及四维事实，操作同时标为 completed。
已观察到输出或其他未知效果时保留隔离，不生成无效果收据，也不自动重跑。
释放原资源预留前，须已发布持久隔离或保持全局未知阻断。

准入发布允许严格识别的初始 Prepared journal 尚未物化，但必须核验完整冻结计划、typed claims 和隔离库存。
该资源始终被隔离；发布不恢复、不补写其他 owner 的现场，也不授予快照收尾许可。
启动恢复仍要求实际停止证明，最终 journal 核验仍要求物理与 SQL 一致。

已完整绑定配置组的停止父 attempt 可在 Sealed 状态保留 Prepared，等待配置收尾。
它保留全部隔离，不因子配置已还原而被当作未执行。
专用快照收尾 intent 绑定完成操作、主体、组修订、冻结引用、停止闭包及已封存输出。
只读启动预检先核对这些语义；损坏 intent 不能先推进 SQL 前缀或写恢复 ownership。
仅经完整还原证据核验的 pending intent 可获得专用、可失效的精确 slot 许可。
快照事务再次比较父、子 journal 和配置组游标；完成重放不重新发布旧快照。

`StepWriterScope` 将实际 Job 和根进程绑定父 attempt 的冻结步骤。
进程暂停创建，先持久登记完整身份再恢复运行；配置步骤复用同一实际 Job 形成父、子独立停止闭包。
完整进程族与实际停止证据仍是恢复前提，根退出或输出排空超时不能代替这个证明。
stdout/stderr 捕获使用显式继承句柄、有界解码与队列；丢弃、错误编码和超长行保留不完整标记。
同一管道 reader 在解码前提交原始字节，记录器以有界队列写入不可变 content，并保存逐段来源、字节偏移和实际 EOF。
原始记录写入失败不会阻塞进程输出，但不能据此新增业务成功。
步骤证据绑定实例、父日志、操作、run、attempt、步骤、Job、writer、session 和冻结计划摘要。
实际采集 proof 在原 writer 或配置 controller 的锁内核验原句柄与停止 token；持久写入期间保持证据只读租约。
历史引用发现只读取 manifest 与闭包结构，不重新打开当前脚本，也不为 GC 重新打开待清理的原始 content。

Core 的 `AttemptBusinessJudgement` 管理关键词累积、首个业务判定、步骤 owner 身份、脚本调用 generation 和取消后的迟到结果。
`AttemptFactsPolicy` 按冻结顺序汇总步骤，分别保留引擎、业务、生命周期和恢复事实；单步骤成功不能补齐其他步骤的未核验范围。
`EnteredAttemptRecovery` 管理进入效果后的停止、worker 收拢、Applied、配置恢复与 Interrupted 记录顺序。
它不把 Entered 改成 Sealed，不用退出码推断业务成功，也不覆盖已验证的引擎或业务事实。
步骤结果、取消和父日志发布共用实际实例租约内的有界提交序列；已接受且未结束的发布最多 64 项。
结果 proof 先持有实际 writer 锁，再在提交序列中读取最新持久取消状态；取消先受理时不能追加新的业务成功。
进入效果后的 Applied 与终态由同一 owner 写入，receipt、操作完成状态和隔离投影在同一 SQL 事务提交。
终态发布在实例发布队列内完成恢复核验和执行资源释放；定义保存经过同一队列，看到持久完成后即可保存。
定义资源冲突返回 `409/resource_conflict`，宿主准入不可用返回 `409/host_unavailable`；原操作重放和修订校验保持有效。
启动恢复在全部只读预检后验证明确的日志依赖，先收口父 attempt 的分派和已停止角色，再恢复关联配置子日志，最后用同一个资源管理器执行父收尾。
已安装配置可在旧 creator 和全部必要 writer 进程族停止、独立目标状态已核验后，由同一个输出记录器封存现场；原备份、workspace 或角色绑定无法核验时拒绝写入及恢复。
主任务时长只取实际主 Job 的持久闭合记录，角色已收集也必须关闭配置组准入；缺少真实停止或输出证据时保留隔离和未核验事实。
`ExecutionRuntimeConsumer` 消费实际 inbox，并持有接受时交接的同一资源预留及恢复索引。
步骤 Job 延迟到前驱停止、输出收集及配置恢复后分配；未分派后继不建立假 Job 或成功结果。
消费失败且实际停止尚未完成时保留原 session 和全局未知阻断。
判定输入与解释器边界见[脚本判定](judgement.md)，持久安全重试及完成动作见[调度](scheduling.md)。

PC 目标使用独立 Job，目标根身份在暂停创建后、Resume 前持久登记。
预先存在的就绪游戏不归宿主拥有，强制关闭偏好不授予对它的停止权限。
运行结束时，只有完整进程族、角色、镜像身份和原始 Job 均可核验，才允许保留宿主启动的游戏。
保留 intent 先持久化，再执行实际生命周期交接，最后记录 retained 结果。
重启遇到存活游戏而原 Job 不可核验时，保留隔离和已安装配置，不根据根退出或名称消失推断完整停止。
历史和清理沿用目标证据的不可变引用；损坏的目标元数据阻断清理，不重新执行目标命令。

`TargetFactsPolicy` 汇总主步骤、目标阶段、清理和有序命令，主步骤的业务事实保持独立。
命令事实保存原始身份、顺序和实际引擎结果；只读类型本身不能将失败或未知改为成功。
完整响应明确确认设备离线时，语义解释与原生退出结果分别保存；设备关闭完成要求最后两条连续命令均确认离线。
未知、不完整或矛盾的观测保留 Unknown，失败的效果命令仍贡献 Failed。
同一主导引擎结果的原因依次取主步骤、目标阶段、清理和最早命令。
这些纯事实规则不授予启动、停止或重试权限。
Android 命令由正式运行 owner 在独立实际 Job 内执行，根身份先持久登记再 Resume。
工具、端点及 MuMu 映射来自冻结输入；MuMu 发现是显式、独立的只读操作，dry-run 不启动 manager。
命令共享绑定原始输出额度，完整响应、语义观测与全进程族收集分别保存。
清理决定绑定自身收集时的不可变事实前缀，不被后置钩子期间的取消改写。
未知远端副作用保持隔离，不自动重放；历史与 GC 沿用已保存命令及收集引用。
专项 worker 的授权、控制通道及配置边界见[执行 provider](execution-providers.md)。

正式 TaskAdapter 的任务和已选任务在原 `Step.adapter` 及任务列表中冻结，包/脚本/原安装足迹作为原 blob 闭包保留。仅适配任务而不声明 execution.drive 的专项使用 Host 已选可执行文件的 process 引擎。结束后的观察和重试提案读取初始配置计划冻结的 RunState/Source.Tree 与实际有界完整输出，不读取后来变化的当前配置修订。任务事实作为原 collected step evidence 的引用保存，不改变引擎/业务结论，也不替代原自动重试授权；输出不完整或超限时保持 Unknown。
观察响应可以包含完整已冻结任务表的结果；Host 仅保存本轮已选任务的事实。未知任务身份仍使观察不可用，未选任务的返回值不能扩大原计划或重试范围。

有限重复业务任务通过 `repetitionLimit` 冻结总次数，观察结果中的 `completedRepetitions` 只累计已确认成功的次数。Host 从前次不可变观察推导本次 `repetitionOffsets`，同时交给 worker 和观察器；成功项不再选择，失败次数继续使用原编号。缺少次数证据、次数回退或超出总次数不能授权重试。启动和登录等安全前置步骤按原依赖重新执行，不消耗业务任务的已完成次数。

实时只读预览在每个 step 首次截图时建立一个独立受控 Job domain，每帧短助手嵌套于该 domain。
原主进程及当前执行身份继续决定预览权限；短助手不加入主进程的历史 PID 集合。
domain 固定启用关闭句柄终止、64 个活跃进程和 256 MiB 内存上限；进程恢复前同时完成 domain 与短 Job 成员登记。
原 RunAttempt journal 只追加一条 open 和一条 closed 内联 process participant，绑定冻结计划、原主 writer、SQL creator/root 和派生 Job 名。
单个 UI 预览关闭会撤销自己的授权并等候实际短助手停止；同一 step 重新打开预览复用空 domain。
step 收集先撤销全部预览、停止 domain、等候助手收集，再确认原生空状态和保存 closed，随后继续原最终截图及配置恢复。
冷恢复核验完整 journal 前缀、原 SQL creator/root、固定 limits 与 session；未闭合 domain 还要求原 creator 已停止且精确 Job 已空或不存在。
未知或仍活跃的原生状态阻断恢复；domain 证据不替代原主进程必须具备的停止闭包。

业务跳过在原执行 journal 保存有限的 `binding-skip` 事实，绑定冻结步骤、原因、判定时间及成功额度日界；命名依赖读取实际已收集的前序结果。跳过步骤不创建 worker Job、进程或配置会话。配置候选仍在准入时冻结，配置会话只在实际步骤准备时建立；恢复分别验证已执行配置的还原收据和未开始配置的原始 before 场景。
脚本 `totalTimeoutSeconds=0` 表示不限总时长，`stallTimeoutSeconds=0` 关闭无输出超时。冻结运行的零总预算与最大 UTC deadline 成对保存，单调时钟继续记录消耗；取消、停止、输出额度和收集时限仍保持有效。含不限时步骤的队列使用同一不限时总预算，有限步骤保留自己的停止限制。

执行计划的定义 bundle 保存已经解析的有效绑定及对应用户身份，覆盖组在该不可变快照中置为关闭；数据库中的原始绑定和用户覆盖保持完整。原始实体修订继续进入 source revisions，不为未生效的钩子引入额外物理根。

普通失败在同一逻辑 step 内按冻结上限生成有限 invocation，所有历史 Job、配置会话和原始证据均保留。
当前角色准入只读取本次 invocation；父 journal 的 SQL 成员集合及实际停止核验包含全部 invocation。
配置会话同时绑定逻辑步骤和 invocation ordinal，历史关闭证据不能借用当前会话。
同一 Step+Role 的终态日志按实际调用顺序聚合原 raw 引用，原始身份、全部内容及现有分页语义保持可追溯；各调用共用绑定输出额度。
单绑定总超时保存实际停止后的有限事实，以 `execution_binding_total_timeout` 阻断普通重试；未知或未停止的 writer 仍保持阻断。
原生结果发布先持有实际 writer 证据，再进入实例已有提交序列读取当前父游标和精确 Binding；迟到旧调用不能覆盖当前调用结果。

编译型 adapter 的接受计划同时冻结 compiler 的安装锁、保存来源选择、完整产物及原生资源引用；`CanExecute=false` 不能进入接受执行。
来源重验借用当前计划已有的预留，并为额外输入取得只读引用，保持同一 manager、实际父 lease 及完整释放计数。
受理发布及配置恢复引用核验使用同一配置的 payload 根，正常入口与失败协调不会切换到其他根解释已存在的安装 journal。

运行进度中的 `steps[].logRoles` 来自该 attempt 的冻结计划，仅列出 `main` 和实际声明的 `preHook`、`postHook`。运行卡片只订阅这些日志流；隐藏或卸载卡片释放订阅，取消阶段以 run 的 `stopping` 状态为准。

单次 writer 核验在现有 journal 字节保护租约内复用解析历史，再次核对目录清单、SQL 游标与取消状态；保护数量超限仍执行完整读取。Blob 复用限于同次核验的有界只读句柄，不跨核验持有权限或恢复结论。

取消命令完成持久受理后，运行进度发布绑定原 run/attempt 的 `cancellationRequested`，并立即卸载预览；该标志不代表 writer 已停止或配置已恢复。运行卡片保留到真实收尾完成，后续收集阶段不会重新挂载已取消任务的画面。

Android 命令的同步核验与 attempt 准入读取在各自调用内持有目录和有界 blob 读取租约。目录属性仍从受保护的真实句柄读取；SQL、取消状态及 journal 新鲜度每次重新核对。租约不跨异步等待或运行代际。设备清理测试同时检查持久化的关闭结果和两次离线确认，不能以运行卡片消失代替设备停止证明。

队列依赖使用 RetryDecision.ClassifyCollectedPrimary 的业务成功分类，仍保留实际 Engine/Business 原始事实。
ExecutionPlanBuilder.Freeze 在同步 draft owner 内复用一次 ReadWire；Codec 在同次输入租约内复用解析结果。
专项只读资料由 SelectedProjectSource 捕获，在计划中保存来源路径、物理身份与内容引用；准入复核后观察和重试只读取冻结 blob。

### 队列选择项与配置发布

队列保留有序 scriptIds，允许相同脚本出现多次。冻结计划为每个选定绑定分配带选择序号的 stepId；
selection、配置槽、provider、依赖、重试游标及日志图片均消费此标识，bindingId 继续表示账号配置所有者。
脚本成功依赖只引用当前选择项之前的相应脚本项，不引用队列后面的同名脚本。
同一运行中的重复绑定使用同一冻结输入；只有最后一个相应步骤按已保存声明发布配置，避免中途改写冻结来源修订。

运行受理回执从已受理的不可变计划和持久启动来源取得身份，不读取正在被运行进程修改的输出与配置。
取消目标也先验证同一不可变身份；实际停止、效果封闭、恢复和终态仍由原执行 owner 完成。
受理前取消请求没有持久运行身份，不生成运行历史；已受理且未启动进程的取消保留真实 no-effect 终态。

## 执行证据与增量日志

`AttemptReadSession` 由运行 session 和实例租约拥有，最多 64 个并发读取 owner。
每个 owner 的 journal 保护沿用 256 修订、16 MiB 上限；最多保留 256 个已校验 blob、16 MiB 引用字节。
计划及前缀持续只读保护，新修订增量读取；超限继续普通校验。SQL、writer、权限和效果准入由所属 owner 每次核对。
派生图绑定受保护的 journal 修订；新修订从已验证结构游标继续，整次校验成功后发布新游标。
当前 SQL 登记、取消、writer 与实际效果门禁继续新鲜读取；独立访问和实例结束后的读取重新完整核验。

`StepEvidenceReader.Context` 和 `AttemptWriterState` 选择当前 owner 后借用同一计划与 journal，避免进入局部范围前重放旧前缀。
嵌套父范围切换后，读取和追加跟随实际父级保护，返回时恢复原 owner。同步创建、消费与引用读取覆盖完整调用。
同一当前修订的 writer、结果和完成状态各最多复用 1,024 个解析项；切换修订清空，独立视图仍完整验证。
目标证据在首次完整上下文逐项核对，PC 阶段与不可变目标文本可按当前原文复用解码。

判定日志沿原始前缀增量维护有界尾部，保留跨分片 UTF-8、尾行及最终读取语义。
最多保留 64 个稳定 manifest 结果、128 个原始分片保护和 16 MiB 分片引用；仅消费增长部分。
冷恢复及独立历史读取重新构造相同输入，归档格式与完整原文保持。替换、截断和篡改拒绝沿用旧结果。
终结观察和通知批次可借用 registry 中仍受保护的同一终态证明，具体批次释放见[调度与通知](scheduling.md)。
可见面板的增量刷新与释放由[前端状态](frontend-state.md)定义，持久日志继续保留完整原文。

## 活动执行读取

`AttemptReadSession` 持有同一 attempt 的冻结输入、总执行图与历史保护；普通 journal 读取和追加借用同一拥有者。
同一次同步发布共享目录库存和祖先属性，追加前后刷新库存；独立历史访问、冷恢复及保护结束后重新核验完整输入。
停止轮询按运行库已提交变化刷新取消事实，独立观察者比较自身持续连接的 `data_version`。
绑定、资源声明及门禁共享一致 SQL 快照，writer 与取消也在一条短事务读取；无关业务库提交保留已有派生图。
进程、Job、停止证明、资源与实际副作用准入按当前事实核对，时限使用单调时钟。

一次同步验证最多复用两个原始修订、合计 32 个视图及 4 MiB 派生文本；原始修订和总计划必须属于当前拥有者。
历史拥有者按同一修订及总计划复用作业和任务覆盖投影。活动 attempt 的原始修订另由 `AttemptReadMemo` 保存
作业、结果、覆盖、重试和不可变投影视图，每个 owner 最多 1024 项、256 个投影、每份 32 个视图。
全局按原始文本八倍、派生文本四倍及条目开销计量，最多 64 MiB；容量不足使用完整读取。
修改的 JSON、不同总计划和未登记视图继续拒绝；保护结束清除缓存。缓存不保存当前 SQL、进程或副作用授权。

## 实时截图缓冲

PC、Android 和 MuMu 的实时 PNG 在内存中接收与验证，每帧至多 8 MiB。
PC 多帧继续检查顺序、帧数及总大小，预览只保留第一帧返回。取消、进程归属、步骤并发和发布门禁保持。
实时预览不写临时 PNG 或 blob；执行证据及历史截图继续归档真实 PNG。
隔离验证覆盖连续单帧/批量预览、超限、截断、取消和各设备接收边界，同时核对归档入口仍可保存及读取有效 PNG。
