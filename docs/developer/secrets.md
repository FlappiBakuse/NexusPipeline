# 秘密字段持久化

Core 的 `SecretMutationPolicy` 决定 revision 冲突及 keep/set/clear 的引用结果。
Platform 使用当前 Windows 用户 DPAPI，分别绑定 instanceId 与 secretId。
新实例的 secrets 根使用受保护的继承 ACL，仅当前用户和 SYSTEM 获得完全访问；密文、密钥和收据继承这一范围。
字段状态只暴露 revision、secretId、configured、readable，不返回密文或保护元数据。

秘密字段显式区分 Extension 与 Host 所有者。扩展字段绑定实际 activation 的 extensionId；
宿主仅使用当前 instanceId 下的 `proxy-password`，扩展名为 `host` 也不能访问这一字段。
两者复用同一字段表、DPAPI 载荷、准备事务及恢复流程。未知命名空间或跨实例宿主字段在启动预检中只读拒绝。

脚本判定计划冻结代理模式、地址、用户名，以及密码的 secretId/revision 引用。
执行准备借用实际共享根的 `secrets:fields` Reference 租约，检查已配置载荷可读；受理事务再次核对同一引用和冻结设置修订。
这一借用持续到执行准备释放，阻止凭据替换。可信宿主只通过不透明准备对象使用密码，普通秘密读取入口拒绝 Host 字段。

密文候选先在 SQL 登记精确身份，再独占创建文件并刷盘。
引用提交期间保持校验过的只读句柄，阻止对应文件被修改或删除。
字段引用、操作结果与完成状态在同一 SQL 事务内提交。
未完成候选只占用自己的密文范围，不会成为已配置字段，也不自行删除未知字节。

幂等身份包含主体、字段、预期 revision 与变更种类。
Set 重放核对绑定操作身份及秘密内容的 HMAC，拒绝同一 operationId 携带不同值；普通请求摘要不包含明文或其裸摘要。
实例随机密钥在首次建库时由当前用户 DPAPI 保护，独立文件保存密文，数据库只保存其身份、摘要、用户与大小。
密钥缺失或损坏时不重建。原密文退役后仍可验证原操作，重试保留首次接受的结果；当前可读性须另查字段状态。
候选准备和未闭合恢复期间持有已核验密钥文件的只读句柄，防止校验后的密钥字节在发布前被替换。
损坏、缺失或不属于当前用户的载荷仍保持 configured；读取失败不会隐式执行 Clear。
Set 替换及 Clear 在同一事务中登记旧载荷退役、精确 `fileCleanup` journal/outbox 与新的字段引用。
可验证的旧密文使用原生文件/父目录身份和摘要冻结清理计划；秘密保护密钥不在可清理的路径集合中。
清理在 DELETE 保护句柄下重查当前引用；历史结果由 HMAC 保留，不再占用旧密文。
已经缺失、损坏或不可证明身份的旧密文只登记未验证退役事实，不获得删除计划。

正常清理要求实际实例租约、全部资源的变更租约，以及当前进程完整身份与已登记的无 worker 执行者身份。
仅排除该已证明的当前执行者；其他 writer 仍须有停止证据，重启恢复继续使用原生停止检查。
执行中出现未知文件身份或字节时保留文件并隔离对应秘密载荷资源。

`SecretFieldService` 使用同一实例租约和共享变更准入；新操作完成后尝试拥有权已证明的清理并发布真实恢复索引。
旧操作重试在新变更准入之前核对原结果，不重新建立已撤销的字段引用。

`PreparationPlanCodec` 冻结 `nexus.secret.preparation-plan`/1：绑定旧字段修订、加密候选、重放校验、父目录身份和原始清理计划。
冻结保持原字段和旧密文可用，候选密文仍驻留准备对象的内存中；导出的计划字节与解析对象不能改写冻结事实。
`nexus.secret.preparation.receipt`/1 区分 started/completed，完成收据必须绑定新文件身份。
Core 恢复规则要求完整 writer 停止及独立候选证据；已闭合历史不要求重建后来退役的密文。
实际 Set 使用专属 `secretPrepare` 类型：接受事务登记候选、writer、门禁与 outbox，进入门禁后独占创建密文并刷盘。
started/completed 独立收据绑定已登记 writer、冻结计划、摘要及文件身份；持有候选只读句柄后才在同一事务公开引用、原结果和旧密文清理意图。
同 operationId 的并发调用使用有界请求预留，等待原调用后仍从 SQL 核对完整身份和内容，不缓存另一份秘密事实。

完整诊断在副本预检所有类型，再核验原生 creator/Job 停止。
尚未进入效果门禁且确无文件/收据的准备可取消；已经进入而证据不完整的现场保全隔离，不重新写密文。
完整独立收据和原字段修订仍匹配时可公开候选，已记录 committed 而 SQL 落后时仅补齐同一事务。
未知 writer、摘要或额外收据在原始 DB 打开前拒绝；取消、隔离与已发布操作分别保持原重放结果。
真实 OwnedWriter 强杀验证十二个写边界及重复恢复；收据损坏另有原始运行根逐文件指纹保全检查。

Host 已组合同一个 `SecretFieldService`，并提供 `/control/v1/secrets/{extensionId}/{subjectId}/{field}` 状态入口。
明文只由独立 `POST .../read` 请求返回 UTF-8，响应使用 no-store、nosniff；读前和解密后复核实际本机权限。
`POST .../change` 使用独立操作、修订及 keep/set/clear 头。Set 只接受严格 UTF-8 正文，最多 196608 字节及 65536 UTF-16 单位；其余两种正文必须为空。
请求和响应的受控秘密缓冲区在结束或异常时清零，不生成通用明文 DTO、幂等响应缓存或请求体日志。
Host 按已保存设置选择本机或远程监听；秘密明文入口仍仅接受实际本机 peer，并核验监听 authority 和严格 Origin。
所有本机操作方共享 Windows 用户信任边界，不能从客户端头声明身份。
当前秘密逻辑主体由服务端校验的扩展、对象及字段组成；全局 operationId 不能跨字段重用，也不能改变同一操作的秘密值。
专用状态 schema 拒绝明文、密文和草稿字段，未配置状态不能声称可读。

远端 Bearer 首次加载核验完整生产链，在持有文件句柄和恢复修订不变时复用证明；每个授权点仍复核当前 SQL、载荷身份及恢复状态。
授权在现有执行发布队列内读取稳定状态，不将正常发布中间态当成凭据失效。
秘密文档发布只允许当前已鉴权请求继续复查其原凭据；续行须持有实际插件数据和秘密字段变更预留，并绑定该次发布的精确恢复投影。
续行仍核验当前凭据生产链、SQL 引用和载荷句柄，不授权新请求、其他证明、已结束请求或后续未知投影。
拥有该预留的事务直接执行相同复查，避免 SQL writer 等待排队发布者、发布者又等待该 writer 的锁循环。
正常活动 journal 仅在其 writer 完整匹配当前 Host 时允许；旧 writer、凭据生产者隔离、quarantine 和全局未知仍拒绝。
轮换或 clear 先释放旧证明并阻止并发加载；旧长连接在下一授权点失效。关闭远程访问同样撤销既有 SSE。

已提交变更通过持久化 fileCleanup journal 清理自己拥有的退役文件；准入冲突或无法核实拥有权时保留原字节，由恢复流程核对。
完整实例备份按用户指南在正常退出后保存整个运行目录；当前没有独立备份按钮。
此实现不承诺跨 Windows 账号或跨机器恢复，也不承诺物理擦除已退役字节。

### 退役 payload 的清理

通知和扩展文档的批量秘密变更，在进入发布隔离前预留每份冻结退役计划的专属资源租约；
新引用提交并完成子发布后，由同一拥有者执行旧 payload 清理并重新发布恢复索引。
清理继续验证计划、物理身份、引用和其他 writer 停止证明；不删除无法确认的字节，也不以 HTTP 回执到达与否决定清理。
