# 配置存储与编辑协议参考

适配器资源的 `relativePath` 表示配置快照内路径，单文件快照使用空字符串。
`sourcePath` 由 Host 从已绑定的同一脚本根和配置声明生成，表示来源相对路径，供稳定实例识别；
它不授予文件读取权限，也不替代 patch 的快照路径、摘要和修订。

配置归属由 bindingId 和不透明 resourceId 标识，主、附加配置分别比较修订。
resourceId 是逻辑标识，不直接组成文件系统路径。
配置契约冻结自己的修订、定义摘要和已选择实例；不使用插件产品版本代替配置契约身份。
严格实例契约缺少显式选择时拒绝保存，不自动采用共享配置。

`ConfigurationRevisionPolicy` 拥有配置 CAS 和契约匹配规则，`FileTreePolicy` 冻结有界、规范排序的文件树。
快照支持原位不存在、文件和目录；文件元数据指向不可变内容 blob，不把配置正文复制进 SQL。
`nexus.configuration.snapshot`/1 保存规范文件树，SQL 保存修订、当前指针、契约和资产关系。
未知快照、缺失当前指针或不一致的资产闭包在完整诊断副本上拒绝，不采用旧修订作为默认值。

`ConfigurationRevisionStore.Prepare` 只接受已存在并能核验的内容，冻结规范 manifest 并持有文件及父目录。
它不替换外部脚本现场。未引用的不可变准备内容由后续保留/清理流程处理，不被当作已提交配置。
SQL 在同一事务比较 binding/configuration 修订，提交新修订、当前指针、资产关系及原操作结果。
SQL 失败保留旧配置指针；相同 operationId 返回原修订，不把它重新设为当前配置。
当前和历史配置引用共同保护内容；历史清理和删除后的资产退役由保留流程处理。

`ConfigurationBatchService` 在同一准入中取得主、附加配置的全部资源，最多合并同一绑定的 32 个不同资源。
全部内容和 manifest 在 SQL 事务前完成准备并持有核验租约；SQL 中统一比较绑定修订及每个配置的原修订。
一个资源失败则所有指针、历史、资产引用、逐项结果及操作接受一起回滚。
返回结果顺序按 resourceId 固定；无变化修复保留该项原修订，其余变化项仍可独立递增。
已接受操作重放返回整组原结果，不重设当前指针，也不重新准备已经退役的原内容。

Host 组合的 `ConfigurationRevisionService` 复用实例租约和共享定义、blob、配置资源准入。
已接受请求的重放先核对完整主体及请求摘要；新保存不能绕过关闭、恢复或冲突资源。

不超过 4 KiB 的快照在同一不可变文件保护内复用冻结树，每次打开仍核对物理身份、长度与完整引用。
最后一个保护释放后清除解析结果；不同 runtime、引用及重新打开的变化文件独立校验，较大快照完整读取。
文件树扫描按受保护文件的实际长度读取，保留全部字节摘要、容量和长度变化检查。

运行满 15 秒后仅尝试一次中间同步；结束同步按有效策略执行。内容与目录文件数判据见[配置生命周期](configuration.md#自动同步)。显式导入与自动同步各自使用已有事务 owner。
每组运行资源只登记一个共同的 writer Job，准备状态也不能另行预登记第二个 Job。
首次关闭准入时冻结单调时长；写库失败后的等待和重试不改变可信时长，也不能重新启动 writer。
停止闭包同时绑定这一时长与整组资源，SQL 中的关闭时长必须与闭包一致。
运行中间同步产生的每份历史修订均核对 manifest、契约与资产闭包，不能只验证最初和当前指针。

## 读取现有配置

`ConfigurationImportService` 将绑定已声明的文件或目录读取为 Host 内的不可变快照，不修改原脚本目录。
请求只提供绑定、脚本及资源的预期修订，不接受外部路径；专项资源还须包含已声明的文档。
全部资源共享定义、物理文件及配置准入，拒绝链接、运行目录、重复或重叠路径，并限制总文件数和字节数。
读取期间持有原文件及目录，提交前重新核验文件树、物理身份和资源声明；全部配置修订在同一事务发布。
相同 operationId、主体和请求返回原批次结果，即使来源已经变化或消失也不会重新导入。
Web 的“读取现有配置”和 CLI `configuration-import --input <JSON>` 共用此用例；要求 `configuration.edit`，MCP 不开放。

## 字节补丁

`nexus.config.patch`/1 绑定 operationId、resourceId、源摘要和源修订，每个编辑同时声明 expected 和 value。
`expectedExists` 缺省或 true 要求目标已存在，实际 null 仍是存在的值；false 必须同时声明 expected=null，只能向已存在对象添加缺失的最后一个属性，不创建祖先或增长数组。
公开 C#/TS 消息、Host reader/writer 和适配器配置意图共同保留这一条件；插件不能在返回提案时改变用户授权的存在性。
选择器是属性名、数组索引或 `{"match":{"property":"id","value":"stable-id"}}` 的数组；点号只作为属性名，不解析旧路径语法。
匹配不到或 ID 不唯一时拒绝，父子编辑及指向同一节点的重复选择器不能组合提交。

`ConfigurationDocument` 只对显式声明的 JSON、JSON-with-comments 或 YAML 进行结构化读取；不透明资源不解码。
原文独立持有，结构按需解析并保留 UTF-8 字节跨度。替换仅覆盖授权值，不重新序列化整份原文。
BOM、LF/CRLF、中文/emoji、范围外注释和空白保持原字节；输出重新解析并与预期语义核对后才返回。
无变化修复保留原始引号和转义，不递增配置修订。

JSON-with-comments 必须单独声明；标准 JSON 保持严格语法。
YAML 使用锁定的 YamlDotNet 18.1.0 事件解析器，限制单文档、32 层、8192 节点、2 MiB 正文和 256 KiB 标量。
锚点、别名、显式标签、merge key、重复键和非有限数值拒绝，不将它们静默改写为另一种数据。
读与写分别授权，保护选择器覆盖的值及其父对象不能通过一般补丁访问或替换。
稳定 ID 的修改也不能使保护选择器失效或重新指向另一对象。

`ConfigurationPatchService` 的预览只读取已保存且经核验的内容，不写 blob、修订或外部脚本现场。
提交复用配置资源准入，将候选持久化为不可变内容后，用同一 SQL owner 比较绑定/配置修订并公开引用。
完整提案和声明上下文只以请求摘要绑定操作；不会在操作记录中存储补丁正文。
重建用例后仍先验证原请求并返回持久结果，不为重试重新读取旧源内容或覆盖更新后的配置。

`PatchBatchService` 接受 Host 已确定的逐文档地址、相对路径、语法、访问范围与当前补丁提案。
这些参数不构成插件修复授权；普通 Generic 原始保存不调用补丁批次。
正式 TaskAdapter 使用原脚本 `adapterResources` 对已登记配置路径和已保存快照内文件的显式声明。
实际发布的包必须声明 `configuration.edit`；Host 同时核对当前安装修订、绑定/配置修订及 `AllowConfigRepair`。
候选摘要绑定源及完整提案，确认后重新调用实际适配器；候选变化即拒绝。
原 `ConfigurationDocument` 先对声明的 Write/Protected 验证全部编辑，再把写入范围收窄到精确候选选择器，禁止 descendants 扩权。
提交借用同一实际 Mutation root，复用原 `ConfigurationPatchService` 与配置 CAS；操作重放核对原主体、完整选择和候选摘要。
公开请求不能提供语法、访问授权、外部目标或任意补丁正文。其他 ConfigProvider 注册及发行接入范围独立维护。

一组最多 128 份文档提案、合计 2 MiB 补丁正文，以及同一绑定内 32 个配置资源。
预览深冻结逐项访问范围并复制补丁字节，严格绑定输入顺序及精确字节摘要；格式化不同的提案也不能重用同一操作。
每个文件调用原 `ConfigurationPatchService.Preview`，同一地址的不同文件合并成一棵候选树，每个资源最多发布一份修订。
重复或大小写别名路径、混用操作/绑定、同一资源的源修订或契约不一致均拒绝；全部文件通过后才允许持久化候选。
预览拥有每个源 blob 的只读租约和独立候选，释放时清除候选；预检失败不写 blob、SQL 或外部现场。
提交一次取得全部共享资源，经原 `ConfigurationBatchStore` 在同一事务提交全部配置 CAS、资产引用和结果。
批次可附 Host 冻结的只读依赖，最多 128 个文件，全部属于同一 binding 及绑定修订；依赖地址、契约、配置修订、相对路径和原 SHA 一起绑定请求摘要。
提交 reference-hold 只读资源，并持有实际不可变文件及父目录句柄；候选提交的同一 SQL 事务复核全部依赖，不把相同字节的新修订当作旧来源。
只读依赖和写入资源重合时复用该 Mutation 预留；依赖损坏或变更使整次接受和发布回滚。已完成的精确重放只返回原结果，不重新授予写入或读取已变化的依赖。

`configuration_batch_results` 与逐项结果由该 publisher 在同一事务写入；普通批次、编辑保存与运行同步共用这一 owner。
补丁批次使用 `configuration.patch-batch`，结果头记录完整有序请求摘要；普通发布的源请求摘要为空。
重放先核对主体与整组请求，使用历史结果树和冻结请求重建原操作摘要，不重新读取已退役的原始内容。
完整诊断核对结果头、完整数量/顺序、操作种类、摘要有无及格式、历史快照与资产闭包；缺行或缺头不能变成部分成功。
定义合法删除后仍保留历史配置 owner；当前绑定仍存在时核对其不可变账号/脚本身份，历史结果重放不重新授予写权限。
没有原请求时无法证明任意合法摘要对应的正文；携带完整请求的重放还必须通过原 `operations.request_digest` 核对。

## 任务选择

`TaskSelectionPolicy` 接受明确授权 ID 集合及类型化任务来源：带 ID 的对象数组、布尔键值表、ID/布尔并行数组或任务 ID 与布尔选择器的显式映射。
显式映射要求每个授权 ID 恰有一个非根选择器，禁止多个任务指向同一字段；映射按任务 ID 规范排序并随运行状态持久化。
适配器任务可声明 `projection`，固定原资源 ID、相对文件及选择器；Host 在原定义语法和读写/保护范围内创建运行任务规则，不接受由该声明扩大的资源权限。
首次运行保留 `isEnabled` 对应的原始开关，核对其与保存快照中的布尔值一致；父项未选择不会清除子项原值。冻结规则必须完整匹配原任务映射，不能换入其他选择器。
`retryPrerequisites` 只记录冻结依赖中的显式前提，不改变任务的安全性或业务角色，也不单独授权执行重放。
新进程所需的登录等安全技术前提，即使上一轮成功，也随失败业务重新执行。没有投影的收尾步骤仅在明确声明安全时保留原生命周期配置；未知副作用不能借收尾角色绕过安全校验。
适配器的普通失败重试读取已收集的原始输出和任务观察，只接受原先启用、已选择且声明安全的失败业务叶子及其显式安全前提。顺序执行在失败后停止时，可同时续跑有明确 `unknown + notExecuted` 证明的业务叶子；必须存在该次调用的失败事实，普通 unknown、partial 和成功结果不能作为重试目标。
下一次持久调用绑定上一 Job、原始输出、观察摘要及规范化子集；配置仅启用子集中的映射字段，保持原快照、初始开关和进度发布游标。
失败子集续跑另行冻结上一配置会话实际发布的快照作为运行输入，保留其计数、日期及进度；原配置快照和初始开关继续用于归属与恢复。输入引用须与该已完成会话的精确发布修订及摘要一致，纳入持久引用和只读恢复核验。
没有任务开关的附加配置同样接续该会话的发布快照，不能因其任务映射为空而重置进度或拒绝整组重试。
没有合格提案、映射不完整或前提不安全时结束该项重试，不改为重新执行全部任务。
新观察保留本次原始结果，只替换实际子集内的结果；其余任务沿用原观察，完整报告与恢复读取同一证据链。
`observe` 请求的 `tasks` 保持原始冻结任务表，`selectedTaskIds` 则由 Host 的持久调用记录给出本次实际执行集合，包含安全技术前提和保留的安全收尾。适配器用此集合解释日志顺序，不从缺少日志猜测任务已执行；`retry` 响应中的同名字段表示建议重试的业务目标，不单列技术步骤。
没有独立任务开关、由上游原入口持久进度负责续跑的业务，可冻结 `nativeResumeScope`。Host 核对其覆盖全部原选中任务、没有混合配置投影或 partial 结果后，重入原入口并重新观察整个范围；不得把这一声明当作任意全量重跑授权。
合成安装插件已覆盖原生 worker 的两次持久调用、配置还原与历史成功保留；各专项插件的前提与真实上游执行仍须分别验证。
初始选择单独冻结；选择时只生成指定且获授权的布尔字段补丁，未列入的条目和参数保持原字节。
恢复初始选择时重新按稳定 ID 定位；数组顺序改变或新增未授权条目不会使旧索引指向另一任务。
并行数组要求长度、ID 唯一性和所有布尔类型匹配；缺失、重复、错误类型与越权提案拒绝。
读、写和保护范围仍由 `ConfigurationDocument` 校验，任务辅助接口本身不授予额外权限。
`ConfigurationPatchWriter` 将 Core 提案转换为当前 SDK DTO 并通过同一 schema；实际保存继续走补丁 CAS 用例。
运行会话的持久初始状态使用 `nexus.configuration.run-state`/1，由 `AttemptRuntimeSession` 在执行与重试时消费。

`ConfigurationTaskTransformation` 从已保存修订的真实 blob 捕获开关，再生成选择后的独立候选。
恢复只修改进度副本中的获授权开关，按当前稳定 ID 定位，保留完成计数、新任务和其他原始字节。
原始 blob、初始布尔值、完整任务声明、操作身份、资源和修订必须一致；恢复不接受外部现场路径。
只读候选核对计算预期输出摘要，不发布内容。

`RunStateCodec` 冻结账号、脚本、绑定修订、配置契约、原始快照、自动同步选择和初始任务映射。
受控配置交换计划可引用该状态；父 attempt 对齐对应步骤的账号、绑定修订和已选任务，专项执行要求开启同步。
准备租约及 journal 引用闭包同时保护原始快照和选择后的候选；GC 查询只读取元数据，不重开正在删除检查中的内容。
冻结与变换接口只操作不可变副本；原位安装、writer 和同步由运行配置组管理。

`ConfigurationRunPreparation` 从实际定义库及配置修订库准备交换计划；冻结步骤的账号、绑定修订、脚本、根、命令和配置/日志路径必须一致。
主、附加目标复用 `ConfigurationTarget` 及同一现场路径规则；运行要求已有快照和明确写范围，不从外部现场猜默认配置。
每项配置拥有独立操作、journal 和计划，候选选择不修改现场，原始和选中内容都由准备租约持有。
运行准备借用 Host 共用资源管理器签发的父租约，核对实际 manager、操作与全部引用/变更模式，不另行获取自冲突的子租约。
父调用方释放租约后，已接受的借用继续保护资源和宿主写入；最后借用及已进入的同步回调结束后才真正归还。
普通脚本冻结独立的首次检测与结束同步选择；内部总许可关闭时两种触发均关闭。专项执行必须保留结束同步。准备接口尚不登记运行组、启动进程或公开进度快照。

## 运行配置组

`ConfigurationRunStore` 将组绑定到实际接受的父 attempt、步骤和全部配置子计划；每项资源保留独立操作与 journal。
接受事务统一登记组、资源、模式、文件 outbox 及原修订；任何一项失败则全部回滚。
进入 Running 前核验全部现场已实际安装，绑定与配置修订仍一致。
编辑和运行共享同一个原生 writer owner；运行命令来自冻结步骤，根身份在 Resume 前持久登记，停止核验整个 Job 进程族。
停止收据按组核对完整 journal 集合与各自的配置子操作，不将组操作冒充子计划身份。
配置来源和停止检查借用活动 attempt 的原始历史、完整执行图和当前修订解析结果；
进程、Job、停止证明、资源与 SQL 关系逐次核对，保护规则见[活动执行读取](execution.md#活动执行读取)。

`ConfigurationRunController` 在配置作用域内安装、启动、定时采样和结束；准备对象持续持有真实父租约借用。
周期采样只接受当前组的真实 writer 计时与最新阶段，核验原工作区、备份及未授权对象的原生身份。
采样在不可变副本上还原初始任务标志，保留完成计数和新任务；现场仍保留执行中的选择。
声明文档验证与原始、当前快照的收缩保护通过后，规范化内容及 manifest 保持实际读取租约直至提交。
`RunProgressStore` 原子提交有变化的快照、逐资源游标、同步序号和逐项结果；无变化不新增快照修订。
结束先关闭准入、停止 writer 并封存 raw 输出，再恢复原对象，最后将最终同步和组终态一起提交。
SQL 失败保留旧指针及恢复占用；明确重试使用同一封存输出，已提交操作重放不再次采样。

`ConfigurationRecoveryHolds` 统一投影未结束的编辑和运行；运行按父操作聚合相同资源并保留冻结模式。
子 journal 已恢复不代表运行组已完成。启动库存核对组、同步历史、历史快照资产与完成操作，不释放仍未结束的组占用。
`AttemptRuntimeSession` 组合运行组、周期同步与最终收尾；公共配置用例通过同一服务读取修订、提交补丁及管理编辑。
跨进程运行组收尾使用持久停止闭包中的可信单调时长，不用墙钟时间差授权最终同步。

## 持久编辑会话与现场

`ConfigurationEditStore` 在同一接受事务保存会话、主/附加资源的配置与绑定原修订、契约身份、专属冻结计划、journal 和文件 outbox。
一项资源失败则全部登记回滚；同一绑定同时仅有一个未结束会话。
准备前先拒绝 runtime、runtime 的父目录、卷根及相互重叠的目标，不先归档再判断路径权限。
开始时没有用户快照的资源使用显式捕获的原形态作为候选，不按扩展名推断。

`ConfigurationEditExchange` 使用产品文件适配器独占创建同卷相邻工作区，保留原对象、安装冻结候选，并为每一步保存文件收据和 SQL 投影。
原始对象恢复使用原生身份核验；恢复不写用户快照。
SQL 中的会话进入 Editing 前重新比较全部绑定和配置基线；并发变更不会被编辑开始动作覆盖。
当前执行者仅豁免自身协调进程的存活，所有已登记 Job 仍须真实证明停止；Job 缺失且无有效停止收据时保持未知。

保存/取消必须核验全部 journal 已提交和原现场已还原，并持有原场景文件及目录租约直到 SQL 事务完成。
保存将全部配置修订、资产、逐项结果及会话终态一起提交；失败保留未结束会话和原快照。
取消只改变会话状态，不写用户快照。主体、完整请求摘要和会话修订分别校验，重放直接返回原持久结果。
完整诊断在副本上核对会话与历史基线、journal 和完成操作的闭包；未知元数据拒绝，原始数据库字节保全。
重启恢复后，未进入编辑且已完整还原的准备会话取消；已进入编辑的未结束会话继续保留独立资源占用并阻止宿主退出。

`EditCompletionService` 在 Host 中共用实例租约、资源管理器与恢复索引。
它只接受全部现场已还原并提交恢复 journal 的会话；不负责启动编辑器或修复隔离现场。
保存/取消以当前恢复索引签发的本机会话续办对象取得该会话配置槽的独占租约。
续办逐次核验来源索引、子系统、操作身份及冻结资源集，不能忽略未知恢复、隔离或其他任务占用。
恢复完成后的两个账号可各自结束自己的快照事务，共享脚本和定义占用仍阻止新的外部效果。
提交成功后重新发布未结束会话的占用；事务失败则保留原占用与原快照。
发布使用索引修订比较，过期清单不能覆盖较新的占用；未变化的清单不使已有退出许可失效。
退出等待期间只允许完成退出请求之前已接受、且资源集合未扩大的意图；许可发出后不再接受续办写入。

## 受控编辑器输出

编辑开始计划可冻结 `editPolicy`，显式声明资源内允许写入的相对根和结果形态；缺省不授予启动编辑器的权限。
`ConfigurationEditorProcess` 在原位安装前登记一个独占 Job，原位安装完成且会话进入 Editing 后才允许启动已校验摘要的二进制。
根进程身份在 Resume 前落库，完整进程族由 Job 事件与 accounting 交叉核对；停止首先持久关闭整项编辑的 writer 准入，已预登记的其他编辑器也不能迟到启动。
停止事实持久化为 `nexus.writer.job-closure`/1，记录实际 creator、根进程、进程族和零活动数。
收据发布失败可重试同一已停止事实，不重新启动程序；没有有效收据的消失 Job 不被视作已停。
真实 Job 仍显示运行，或收据中的任一旧进程未停止时，已有收据不能绕过当前观测。

`EditOutputRecorder` 只接受本机活跃编辑器用例签发的停止对象；外部 JSON 不能构造这一权限。
它核验原工作区、完整原对象备份及 writer 停止，冻结 `nexus.configuration.edit-output`/1，并追加独立输出引用和 journal 收据。
封存从同一实例租约借用执行者映像摘要，当前进程与文件身份继续核对，持有期见[进程拥有权](process-ownership.md#映像证明的持有期)。
开始时的计划和工作区证明不改写；恢复视图通过输出计划取得新的候选清单和原生身份。
差异必须落在已授权范围内；范围外的内容或原生对象身份变化都拒绝，即使替换后的字节相同。
采样和封存时重新检查每个输出文件的硬链接数量；运行后新增的别名也不能成为独占输出。
未真正启动编辑器的停止对象只能封存完全相同的原候选，不能接管后来出现的字节。
快照保存使用这一冻结输出，取消保留原快照；两者都先还原外部原对象。

主、附加资源各自封存。封存计划尚未发布时宿主退出，未知编辑字节与原对象备份保留隔离；已持久发布的输出可在新进程中还原原态。
停止收据与输出格式均独立核验，引用关系保护未完成恢复所需内容。
这些机制不承诺识别任意第三方的瞬时写入；布局无法可靠独占时仍须使用独立工作副本或拒绝该模式。
`ConfigurationEditController` 已由 Host 组合，共用实例租约、资源管理器及恢复索引。
开始编辑前先校验目标，再冻结编辑器映像路径/摘要、参数与工作目录；这些字段同时进入操作身份与各资源的专属计划。
受控启动只能使用同一命令，不接受后来替换的路径或参数；幂等开始返回原会话，不重新启动进程。
控制器保留脚本、配置槽、内容引用及物理现场的租约，直到 writer 停止、输出封存、原对象还原和保存/取消事务完成。
声明的 JSON、JSONC、YAML 文档通过现有解析器校验；不透明资源不解码。
校验或事务失败保留原快照和未结束会话，已还原的现场可明确取消；未知现场继续拒绝接管。

物理占用组合原生父目录/对象身份与规范目录项名称，保护缺失目标、祖先/子目录和不同脚本指向的同一现场。
共享祖先使用引用模式，不把独立的兄弟目标变成整盘独占。
模式随 journal 资源登记持久化，并由完整诊断副本与冻结计划核对；不能把变更占用改成引用后继续启动。
重解析点及目标中有多个硬链接的文件在接受编辑前拒绝，不把共享名字当作独占现场。
原生目录项名称消除大小写与短文件名表示的差异；这些规则不授予任意第三方进程的瞬时写入检测保证。
接受的大小写不同路径仍使用实际目录项名称安装和还原；短文件名叶子别名在编辑前拒绝，避免移动后改变原名称或使冻结参数失效。

真实强杀矩阵覆盖原位安装、停止后的宿主丢失、输出发布及完整控制器的八个生命周期边界。
内层 Job 消失且缺少有效停止收据时，完整诊断在副本上拒绝，不改原 DB/WAL、journal 或外部现场；外层监督进程的收据不能代替它。
输出封存后可重启还原，再明确保存或取消；已完成操作返回原持久结果。
独立跨卷原生分组使用第二个真实卷的配置目标与原运行卷的数据库和 blobs，覆盖缺失、文件、目录原态的保存与取消。
它核对实际卷身份、目标旁同卷工作区、内容 blob 所在卷、原对象身份和最终快照；普通 storage 分组与这一分组分别保存回执。
物理断电验证与进程中断、事务失败验证分列，不从后两者推定物理断电通过。
`RunCompletionService` 复用实例租约、恢复索引与共享资源管理器，收尾已经停止并还原的运行配置组。
它从已登记 Job 的真实停止闭包读取冻结时长；缺失闭包或仍有活动进程时拒绝，不从墙上时间推算运行资格。
曾进入运行的组还须具有每项已封存输出；未创建 Job 的准备组只接受完整的无效果终结证据，时长固定为零。
完成时从封存内容还原初始任务选择到快照副本，主、附加配置与 Interrupted 结果在同一事务发布；现场恢复不修改快照。
收尾保留父 attempt 的独立隔离，不将子配置已恢复当作父执行已完成。
父执行消费原准入交接的冻结计划、配置借用及同一资源预留；专项声明由当前安装与激活权限约束。
Host 组合配置修订、补丁、编辑与运行配置服务，Web、CLI 和 MCP 通过公共控制用例使用相同所有权与权限规则。
现有原生证据来自隔离 writer 和真实文件对象，不宣称已经运行用户脚本或游戏。

ValueService 在入口拥有并解析 patch 一次，内部传 ConfigurationPatchRequest；资源租约前后仍分别查询原操作和核对修订。
原生编辑的 editPrepare/editCommit 由编辑事务选择，仅接受已冻结专项声明的单字段补丁。准备作用候选副本，提交在 writer 停止和最终捕获后执行；取消不运行提交补丁，按原事务恢复原字节。

原生编辑拒绝专项声明的自动执行参数。独占上游声明投影到冻结计划和编辑命令，配置交换前及实际启动前核对同程序已停止；发现活动或无法确认的同名进程时拒绝，不终止外部进程。进程 stdout/stderr 继续使用既有严格 UTF-8 解码。

编辑 hook 的 resource revision 为工作候选的下一修订（saved revision + 1），hash 对应本阶段候选原字节；尚无保存快照时可从 revision 0 准备候选 1。发布仍使用编辑会话冻结的原 ExpectedRevision 做 CAS，候选 patch 不直接写数据库。独占编辑在现有资源 lease 中持有程序物理对象的 mutation claim。

### 专项实例约束与覆盖

插件 specialized.instancePolicy 声明客户端是否由脚本自身启动、Android 支持及配置回写要求；
本地保存、导入和运行捕获都核对当前已验证 manifest。编辑器读取同一声明锁定相关控件。
gamePathResource/gamePathSelector 可声明配置中的游戏路径，探测与绑定目标比较；缺字段或无合法绑定目标保持无法确认，不猜测修复路径。

配置探测的 coverage 绑定 Source 中的 manifest、绑定/脚本修订与各资源 SHA。
仅当已启用业务任务均有受支持投影、可安全重试且无阻断诊断时显示完整覆盖；未知启用项保持部分覆盖，禁用未知项不计入业务分母。
覆盖摘要不替代真实上游运行验证。

### 配置读取验收

通过实际安装的专项插件对比已保存快照与隔离配置，核对显式实例选择、任务发现及阻断诊断。
自动执行、实例入口和配置字段以对应插件已锁定的上游及项目文档为依据；缺少目标时保持阻断。
验收绑定保持禁用，核对原快照和外部脚本目录字节，分别记录实际配置读取结果、插件包及软件来源身份。
