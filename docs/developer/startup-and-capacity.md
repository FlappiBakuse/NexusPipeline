# 启动反馈、容量与最小性能修复

> 当前实现：WinExe 共用入口、同窗启动进度、大库检查副本清理、阶段计时、摘要读取合并和可取消历史后台投影。

## 分开记录用户等待的阶段

| 里程碑 | 表示什么 | 不表示什么 |
|---|---|---|
| 启动请求 | 用户或自启入口已请求创建 Host | 数据库或服务可用 |
| 反馈首次出现 | 主窗口启动视图已绘制并可响应 | 启动工作量已经下降 |
| 数据库准入完成 | 对应实例的检查与恢复准入已完成 | 所有任务资源都获准运行 |
| HTTP ready | 控制传输可用 | 启动更新和正常执行服务一定已就绪 |
| Host ready | 本轮规定的必要启动工作完成 | 网页首屏与图片全部加载完毕 |
| 首屏数据可用 | 当前任务页面的必要数据已可操作 | 所有冷历史索引或图片都被预热 |

测量使用同一源码、同一数据与同一机器，分别记录阶段、数据量、逻辑读取/请求数和实际时间。没有测得的秒数不写成改善百分比。只选择能证明本卡目标的数据规模，不默认跑全部百万历史、全部图片或多轮长压测。

## 已证的大库阻断

当前 `StateDatabase.OpenExisting` 在返回前清理检查副本；`DatabaseCopy.Discard` 使用的通用 `PhysicalObjectDeletion` 拒绝大于 `1_073_741_824` 字节的单文件。检查副本中某个文件超过 1 GiB 会进入失败路径；不是文件组总和超过 1 GiB 即失败，等于边界也不是同一条件。

最小修复针对当前操作创建并独占的检查副本。保留固定数据库成员、父目录/对象身份、无链接和真实拥有权；不能靠取消所有用户文件删除上限或递归清空任意路径解决。无法证明拥有权时保留证据并报告明确原因。

统一验证使用一个正常小实例与一个触达修复边界的有效大库，证明可启动、可读、可关闭再打开及原数据未被清理误伤。空间不足、对象替换等已有保护用例只在本次改动触及时复用；不要为扩大数字再造完整故障平台。

证据：[StateDatabase](https://github.com/FlappiBakuse/NexusPipeline/blob/0bb4d144d92805a2d489c65d0be3b7527c7810fd/src/platform/Storage/Sqlite/StateDatabase.cs#L51-L88)、[DatabaseCopy](https://github.com/FlappiBakuse/NexusPipeline/blob/0bb4d144d92805a2d489c65d0be3b7527c7810fd/src/platform/Storage/Sqlite/DatabaseCopy.cs#L19-L53)、[删除边界](https://github.com/FlappiBakuse/NexusPipeline/blob/0bb4d144d92805a2d489c65d0be3b7527c7810fd/src/platform/Storage/PhysicalObjectDeletion.cs#L26-L47)。

## 减少真正的启动工作量

稳定文件组下，复制和复核链消费 `2S + C0 + 2C1` 的摘要字节，副本不变时约为 `5S`。`S` 是原库组，`C0` 是初始副本，`C1` 是准入后的副本。`DatabaseCopy.Discard` 先捕获最终组并与初始成员比较，再逐对象核验删除，合并了一次相同副本遍历。未知成员、身份替换或字节变化会保留副本并失败。计数表示逻辑摘要读取量。

已完成历史在副本准入与原库恢复中仍各检查一次。数据库源组摘要相同只绑定 SQL 事实；journal、配置树、截图等文件的持有期已退出，历史检查又参与恢复和回收授权。整体跳过冷历史的条件未成立，保持全量核验；不建立跨启动时间戳缓存。归档查找使用一次路径/摘要 lookup，保持内容核验与重复引用拒绝。

### 启动核验的持有期

插件启动批次通过 `ProcessIdentityLease` 只读保护当前宿主映像及父路径，四个并发激活共用一次映像摘要；批次结束释放。单独启用插件仍自行取得保护。每次 writer 核验继续读取进程创建时间、用户、权限和映像物理身份，不使用跨启动或文件时间戳缓存。

单个安装激活期间，原目录与当前目录的 pointer、catalog、signature 文件和祖先目录保持只读保护。使用当前不可变信任策略验证签名和原包成员一次；SQL 接受记录与目录 head 在受保护只读连接内按提交版本重新核验，变化即拒绝。原目录等于当前目录时共享同一验证结果。激活退出释放全部保护，下次启用重新验证。

启动队列按已安装 footprint 的字节量降序分配四个并发槽位，让证据较大的插件较早开始，减少队尾单独等待。该数值仅用于排队，不授予执行权限；每个插件仍重新执行完整激活准入。相同大小沿用原顺序，设置和界面排序保持不变，不按插件 ID 或业务类型设置优先级。

安装证据读取和插件状态列表在同步读取范围内共享实例身份、数据库和有界 blob 保护；回调或请求结束即释放，不跨请求复用未经保护的安装快照。授权、启用状态、安装 revision、恢复阻断与包内容检查继续由原 owner 执行。

安装读取租约持有原数据库文件、父目录和独占的只读连接，以该连接的 [SQLite `data_version`](https://www.sqlite.org/pragma.html#pragma_data_version) 判断 SQL 事实是否发生提交。首次读取完整核验安装绑定、效果、当前元数据和启用状态；其他连接提交后重新完整核验，失败不记为成功。验证事务期间有提交也不保存复用标记。租约不持有跨回调事务，不跨连接或跨请求比较版本；每次仍检查物理身份、journal 名单、当前权限和恢复状态。`installation.sql.validate` 记录实际完整 SQL 核验次数及时间。

插件前端资源读取借用当前运行时已验证并持续只读锁定的包文件。每次借用仍检查完整目录名单、对象身份和单链接约束，打开目标资源时继续核对大小及摘要；不为单个 JS/CSS 资源重新散列整包。借用引用保持原句柄，运行时与全部借用结束后释放；禁用、退役和调用者授权检查仍在读取入口执行。

激活的恢复 SQL 快照、设置 revision 和安装元数据沿用提交版本核验。内存恢复状态、资源借用、激活预留和 writer 进程身份仍逐次检查；任意外部 SQL 提交都会触发相应完整读取，失败结果不复用。`activation.sql.validate` 与 `catalog.sql.validate` 分别记录实际核验。数据库副本准入的只读库存检查共享实例身份、目录和最多 128 个 blob 保护，准入退出后释放；副本与原库恢复不共享 SQL 或文件检查结果。

writer 观察复用激活持有的只读连接，每次建立新的短读取事务，重新读取 writer、job 和关闭证据，并查询实时进程状态。数据库版本相同也不复用进程停止结论；外部提交立即进入下一次观察。连接持有期结束时释放数据库文件及父目录保护。

资源声明库存按每页最多 128 个 journal 读取同一 SQL 快照，再由最多四个工作线程验证各自的计划、冻结来源与完整声明集合。线程独立持有实例、数据库、目录和有界 blob 保护，不共享 SQLite 命令或事务。批次失败等待全部工作退出、释放保护后传播原始错误；副本准入与实际恢复分别完成核验。

所属桌面在创建挂起进程前取得映像及祖先目录保护，摘要只计算一次；启动核验与原生客户端注册在连续保护内复用摘要，每步仍检查进程创建时间、路径物理身份、SID、提权及存活状态。成功注册后保护归原生客户端绑定所有，失败时先停止所属挂起启动再由调用方释放；维护退出等待整个所属进程族停止后释放，不阻挡载荷替换。外部客户端没有这份启动保护，仍自行取得文件保护并计算摘要。用户 SID 比较只读取令牌，不为未消费的摘要读取整个宿主 EXE。

单 journal 的准入检查在证据验证与 handler 准备之间共享受保护的完整修订历史；同轮 blob 读取最多保留 128 个只读引用。数据库的嵌套读取作用域复用外层文件保护，最外层退出时清理原生连接池后释放路径。副本准入与实际恢复保持各自的完整检查和持有期。

首次建立 journal 历史保护时，解析直接读取已经锁定的修订句柄，保留名称、连续修订、实例、阶段和后继约束的完整验证；计划文件由保护绑定步骤锁定并核验一次摘要后才发布。超出有界保护容量的历史继续走完整读取路径，不跳过计划或历史检查。

扩展历史绑定复用计划读取时已校验的 source 解码结果，并重新取得该引用的摘要验证与只读文件保护，持有至最终 SQL 检查结束；footprint 绑定消费同一份 source。独立 footprint 校验仍自行读取来源，后续绑定重新读取当前文件，不跨调用缓存来源或授权。宿主载荷目录使用现役 apphost 基目录规范化入口，不为仅取目录而散列整个宿主映像。

历史工作线程在自己的读取作用域中保留只读 SQL 连接，初次注册信息和最终绑定检查分别使用新的短事务。物理文件保护持续有效，SQL 行每次重新读取；不把先前事务的结果带入下一次绑定。同一绑定事务内的操作身份、资源声明、效果门、目录接受记录与来源设置只读一次，最终设置校验使用这次来源读取；独立重新核验仍完整读取。线程退出先关闭连接，再释放路径保护；不同实例和嵌套作用域保持分离。

效果门与恢复操作族快照也复用当前工作线程的受保护连接，每次调用重新开启短事务并完整读取。已有读取事务内的嵌套调用使用独立连接，维持新提交的可见性；异常退出恢复正常租用。扩展资源声明库存消费计划解码器已返回并验证的 source，再与同一 SQL 快照中的完整声明集合比较，避免同一调用内再次解码及绑定来源。

不可变 journal 文本缓存最多 1024 份、原字节合计最多 4 MiB，另有解析结构开销。缓存只复用与当前读取字节逐字相同的文本解析结果，仍完整读取修订文件、验证目录清单、计划摘要、后继关系与 SQL 绑定；超限按顺序淘汰。缓存不保存权限、文件身份或恢复授权，跨启动不保留。`history.text.parse` 记录实际文本解析次数与时间。

内嵌契约使用一套 schema 图、引用注册表与格式策略，惰性创建。首次求值在写锁内执行；当可达静态引用全部解析后，该根的后续求值在读锁内并发执行。动态、递归或未解析的引用保持写锁；解析其他根时也会独占图，禁止联网补齐 schema。成功摘要集合最多保留 8192 项，短锁只保护集合。每次仍执行严格 JSON、重复字段与尺寸检查，首次验证保留 UUID、日期及 URI 格式约束。`contract.evaluate` 记录实际求值及图锁等待时间，完整历史绑定仍以当前文件和 SQL 证据为准。引用解析与求值的实现见 [JsonSchema 源码](https://github.com/json-everything/json-everything/blob/de5ef333009b20db9a7437b9e6433dfa9bb88d44/src/JsonSchema/JsonSchema.cs)。

provider 安装准备把完整包树与归档的只读保护一次性交给注册，注册时重新检查完整文件名单、路径、对象及父目录身份、大小和单链接约束；连续保护期间复用已有摘要。独立注册与后续执行借用继续完整散列。运行映像闭包逐项绑定已保护包的身份及摘要。回调失败、取消或停止后，真实回调退出才释放其仍可访问的保护。

`startup.profile` 记录数据库准入、恢复及逐插件激活的总耗时，并汇总进程映像摘要、激活状态核验、目录验证、载荷验证、契约解析和数据库连接的调用次数与耗时。`provider.prepare/inputs/runtime.capture/runtime.protect/hold` 区分 provider 输入、闭包与重新持有保护；`managed.load/metadata/callback` 区分托管加载、PE 扫描及插件回调。子项时间允许嵌套，并发插件的耗时也会重叠；阶段墙钟耗时以 `startup.stage` 为准。

细分计时覆盖各 `inventory.*`、`history.protect`、`history.sql-snapshot`、`extension.binding`、`extension.binding-sql`、`contract.evaluate`、`writer.executor`、`writer.identity`、`recovery.publish`、`recovery.configuration`、`execution.reconcile` 与 `providers.restore`。连接打开计时不包含随后执行 SQL 的全部成本，评估连接复用须同时比较 writer 观察及激活阶段墙钟时间。

旧版使用 JSON 配置并直接启动插件，新版还执行数据库完整性、事务历史与 writer 归属检查。比较必须同时记录已启用插件、脚本实例、历史数量及数据格式，分别报告进程启动到 HTTP 就绪和各内部阶段，不把不同准入工作量当作相同数据集。

已完成历史按可用逻辑处理器数、最多八个同步读取 worker 按需领取操作族，每个 worker 在遍历期间持有数据库、目录、实例身份及最多 128 个 blob 引用；每个 journal 的修订保护仍在处理结束时释放。实例身份文件及祖先目录保持只读保护，每次复用仍检查物理身份。所有任务结束并释放保护后再传播原始失败；任一失败均阻止准入，不发布恢复就绪。活动操作的恢复仍顺序执行。

前端入口和样式读取沿用同一次请求的安装证据，包资源读取继承该调用上下文，文件内容、安装状态、作用域及授权检查保持有效。图片读取由实际调用统一取得安装证据。插件前端最多六个并发准备槽位，保持输出顺序；当前页默认只读数据与插件前端激活并行准备，首次展示仍等待就绪或现役有界前台等待结束。会话、当前页、插件准备分别记录浏览器性能标记，桌面通过所属进程私有通道记录签名会话、文档加载与首次可用界面的独立耗时。

### 历史索引补齐

`ExecutionRuntimeServices` 在启动工作任务中运行唯一 `HistoryProjection`，依次补日志目录、图片目录与图片资产引用。每页最多 64 个缺失对象，逐对象检查取消，页间释放读取作用域。现有 `InstanceLease.PublishExecution` 和数据库写门负责串行发布。停止等待任务结束；重启重新查询缺失行，已提交页直接复用，无额外游标文件。

活动 journal 准入、writer 停止证明与恢复仍在服务可用前完成。后台任务只处理已收据化的派生目录；正常新执行仍由原终态 owner 同步发布其目录。

`PlanReferenceClosure` 经 `CaptureEvidenceReader.ReadReferences` 从原 journal 追溯未退役图片，因此缺失派生目录期间图片仍受回收引用保护。自动保留期清理等候三类补齐完成，手动退役在此之前返回 `503 history_index_pending`。已有退役证明与清理恢复继续由原 owner 核验。

读取已有目录正常返回；缺失目录返回 `503 history_index_pending`。详情显示“历史索引正在补齐”，可见期间定时重读，隐藏或卸载取消轮询。补齐失败输出有界异常类别并返回 `history_index_failed`，显示诊断与重启提示，保留原记录和文件。

诊断保留 `startup.stage`、`groupBytes/digestReadBytes`、活动/完成 journal 数量以及每页 `projection/inspected/maximum/after`。HTTP ready、执行可用与历史索引完成分别记录。整个启动仍受必要准入工作量影响。

本轮 Windows 定向记录：小库 1,675,264 字节，首次/再次重开约 38/36 ms；大库 1,143,660,544 字节，约 6.66/6.37 s。两者每次逻辑摘要读取均为源组的 5 倍。范围为数据库准入与副本清理，操作系统缓存未清空；没有进行等价 main 性能比较。数据保全、未知字节/替换拒绝、后台续补和图片引用场景通过。

## GUI 入口与进度 owner

根目录 `NexusPipeline.exe` 使用 WinExe，承担手动图形启动和显式命令入口。新建手动快捷方式与安装后运行指向根入口；原 Launcher 及已登记自启路径保留。命令模式连接调用者终端并保留重定向标准流，等待和退出码由调用者持有进程句柄取得。

Host 在必要准入前启动所属 Electron，主窗口通过本地覆盖视图显示真实阶段和已用时间。服务、签名会话及前端首屏可用后移除覆盖视图，并立即记录控制台展示时间；托盘语言刷新不计入首屏时间。外部活动图片与后台历史索引继续独立加载。轻量模式只使用托盘反馈，就绪后按展示意图打开浏览器。

手动启动打开界面，自动启动遵守保存的展示偏好，维护重启沿用窗口恢复意图。启动中关闭主窗口会隐藏至托盘，继续恢复，就绪后保持隐藏。失败显示原因、错误码、复制诊断和退出。

已用时间以渲染进程单调时钟连续推进，并只向前吸收 Host 报告的累计耗时。前端准备进度复用最后阶段快照时不重置计时，隐藏期间继续累计。

私有通道、只读展示快照、原生托盘菜单、图标装配和终端示例的现役说明见 [启动反馈](startup-feedback.md)。Launcher 与 Host 均进入正式装配、载荷校验及维护进程族检查。

## 历史加载的最小修复

日志目录（预览及完整阅读器）和不可用截图目录使用固定行高的滚动窗口，只挂载可见区域及少量前后缓冲。追加分页保留当前选择与滚动位置，键盘方向键、Home、End 可访问全部已加载日志；隐藏时释放行，切换目录重置位置。已加载目录与游标仍由详情 owner 持有，正文读取、截图授权和取消语义保持。

`HistoryReadTests.ServesLargeHistory` 在持久化十万条记录与 10001 个账号的隔离实例上，记录真实认证、HTTP 路由和 SQLite 查询的首个请求及 20 次重复请求。覆盖首尾分页、空组合、账号记录、日期与账号聚合，输出原始样本、响应大小、中位数与 P95。该读模型基准与完整执行 journal 准入、整机启动分别报告。

日期总览读取 `/control/v1/records/summary/days`，只聚合所选时间范围的日期并由日期结果求总量；展开日期的账号页读取 `/control/v1/records/summary/users`，每页最多 200 个账号及一个前瞻项。原完整摘要接口保留同一事务内的总量、日期和账号结果。所有入口继续验证权限、366 天范围、时区、状态与账号筛选，已退役记录排除规则相同。

账号历史具有按结束时间、运行和账号排列的可选只读索引，近期总览可直接定位时间范围。准入只接受登记的精确非唯一索引定义；缺失索引在独占检查副本及已准入库上补齐，未知或改写的同名索引仍拒绝，逻辑 schema 身份保持不变。

详情日志与图片各自保存游标并按需加载下一页，折叠日志不请求正文；日志预览与分段阅读保持有界缓冲。历史索引尚未完成时仅重试未就绪资源。预热请求在同一会话、权限及修订范围内共享，身份或写入变化会撤销；一般状态刷新仍取得当前修订的数据。

当前组合历史在浏览器拉到混合页后才筛选。实际函数探针中，100,000 条纯账号历史需要读取 2,000 页才返回空组合页。把组合条件下推现有服务端查询和游标，按同一条件读取 `limit + 1` 判断后续；不以某一页没有匹配项提前终止。

保持现有结束时间与 runId 的稳定边界、账号身份、取消与退役语义。查询字段名称以实现后的 schema 为准，本页不把拟议参数写成已存在接口。只用能暴露前瞻读放大的代表性数据验证结果和有界读取，不重复做整机启动基准来证明这条查询。

## 原生验收范围

本批代码完成后，使用同源隔离 Windows 产品检查官方 GUI 入口、必要的隐藏自启、进度可响应与关闭后恢复继续、CLI 不受影响。任务触及安装/更新闭包时补对应真实路径；不默认运行所有升级回退矩阵。需要的 Test/Production 权限清单分别核对，结果与未运行项分别记录。

## 前端启动分段

启动设置读取当前宿主路径及当前进程令牌元数据来选择入口和用户 SID，不生成未被消费的宿主映像摘要。自启动命令仍独立打开并完整散列目标可执行文件；注册与执行过程的身份、权限、修订和恢复检查保持。

副本准入将只读领域库存与已完成历史分两路检查；历史最多八个工作线程，库存中的资源声明批次维持最多四个线程。两路各自持有数据库、实例与文件保护，全部结束并释放保护后才检查活动绑定；任一路失败保留原错误并阻止恢复。原库恢复仍重新完整核验历史，不复用副本准入的权限或文件结论。

执行服务组装判定 worker 时直接使用规范化的当前进程路径；此处只选择 worker 入口，不创建进程身份或授权。实际 worker 启动继续执行映像摘要、物理身份、进程归属与任务绑定检查。

浏览器 Performance measure `nexus.frontend.<extensionId>.<stage>` 记录资源读取、模块导入、激活前身份核验、前端激活和激活后身份核验。stage 分别为 `resources`、`import`、`identity-before`、`activate`、`identity-after`；同插件同阶段只保留最近一次记录，失败和取消也保留已消耗时间。计时不记录请求内容、账号或秘密，不改变两次身份核验和展示条件。结合 `nexus.session.prepared`、`nexus.current-page.prepared`、`nexus.plugins.prepared`、`nexus.interface.presented` 及网络时间线判定真正阻塞首屏的工作。

前端通过每插件一次 `/frontend/{activationId}/assets` 批读声明的入口和样式；单次安装消费与包树租约覆盖全部资源。入口最多 2 MiB，最多 16 个样式且每个最多 128 KiB，浏览器拒绝超过 6 MiB 的编码响应或样式数量不符。每个成员继续核对声明、物理身份、大小、摘要与单链接；返回前继续核验当前调用授权和消费所有权。
