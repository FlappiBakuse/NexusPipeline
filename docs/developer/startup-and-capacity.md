# 启动、恢复与历史加载

启动只准备当前实例、当前恢复候选、已启用插件和首屏所需数据。完成历史在用户访问、精确维护或显式诊断时读取。
资源预算和测量目标见[性能与有界资源](performance.md)，活动恢复容量见[状态存储](storage.md)。

## 就绪阶段

| 里程碑 | 已完成工作 |
|---|---|
| 启动请求 | 手动或自启入口请求创建 Host |
| 反馈首次出现 | 主窗口启动视图已绘制并可响应 |
| 数据库准入完成 | 当前实例、格式及本次恢复准入完成 |
| HTTP ready | 控制传输可用 |
| Host ready | 必要恢复、插件与执行/调度初始化完成 |
| 首屏可操作 | 当前页面的关键数据和交互已就绪 |
| 历史投影完成 | 已收据化历史的缺失派生目录补齐 |

各阶段独立计时。HTTP、Host ready、首屏及后台补齐保持各自语义；时间、逻辑字节和内容范围一起记录。

## 普通启动与完整诊断

`StateDatabase.OpenCurrent` 在实例租约内验证初始化 guard、实例、格式和精确 catalog，维护已登记的派生读取索引。
`StartupJournalRecovery` 只处理活动候选及其所需的停止、计划和资源证明；普通启动不创建全库副本，也不遍历完成 journal。
配置恢复占用只核对仍开放会话的 journal；通知启动协调缺失的终结注册和实际待办，已终结来源不进入空队列重放。

`StartupPresentation` 通过查询专用连接读取展示偏好。已有 WAL 使用独占内存索引并关闭自动 checkpoint，
无 WAL 使用只读 immutable 连接；持续保护数据库文件组，非空 rollback journal 保全拒绝，不创建副本或辅助文件。
业务设置由设置 owner 在普通准入后读取，未知格式保留原字节。

`StateDatabase.OpenExisting`、`DatabaseInspector` 和 `JournalStartupAdmission` 提供显式完整诊断与维护准入。
它们冻结文件组、建立自有副本并验证完整性、外键、历史库存及停止证明。源复制与首遍 SHA256 共用一次流式读取，
准入后仍独立核对源组新鲜度。副本回收核对固定成员、大小与物理身份；未知成员、替换及字节变化保留现场并拒绝。

完整诊断的资源声明按至多 128 个 journal 分页、最多四个 worker 校验；完成历史最多八个同步 worker。
每个 worker 独立持有短 SQL 事务和有界文件保护，全部任务释放后传播失败。普通恢复顺序处理当前候选。
活动上限、冻结预算和完整诊断的快照边界保持，见[恢复容量](recovery-capacity-remediation.md)。

配置运行全库核验在同一只读事务内按 sessionId 每页 128 项前进，逐项核对原绑定、历史、资源及 writer。
完成历史不占用单次执行的活动容量；全库读取覆盖超过 4096 条会话，活动执行仍使用自己的冻结边界。
外部 SQL 改动、未知会话和超出活动容量的受理分别按现行准入规则处理，保留原数据及恢复证据。

## 启动拥有期与插件准备

Host 使用后台工作站 GC。扩展、执行和清理借用实例的映像证明，当前进程身份继续逐次核对，见[进程拥有权](process-ownership.md)。
同步初始化共用有界目录、blob 与数据库读取作用域，覆盖日志、图片、预算、重试及调度准入；未知输入继续拒绝。
数据库连接、journal 保护和缓存失效统一见[状态存储](storage.md)。

已安装且启用的插件使用四个并发槽，按 footprint 字节量降序排队，同大小保留原顺序。
大小只决定排队；每个插件仍独立持有资源租约并执行完整激活准入。停止等待所有启动任务和 scope 排空。
provider 输入和运行时闭包先准备，之后进入原五秒激活期限；首屏计时包含全部准备。
安装、包树和权限证明的拥有期见[扩展](extensions.md)。已提交旧工作区交给服务就绪后的分页清理，不阻塞 ready。

重试与日程候选每页 64 项，按数据库提交序号失效。取消库存的全局关联在完整诊断核对，
单个 attempt 读取自己的取消操作并通过索引检查缺失父引用。新执行准入仍核对实际权限、预算与持久事实。

## 历史索引补齐

`ExecutionRuntimeServices` 的唯一 `HistoryProjection` 依次补日志目录、图片目录和图片资产关系。
每页最多 64 个缺失对象，逐对象检查取消，页间释放读取作用域。发布继续使用 `InstanceLease.PublishExecution` 和数据库写门。
停止等待任务结束；重启查询缺失行，已提交页复用，无额外游标文件。新执行由原终态 owner 同步发布目录。

活动 journal、writer 停止证明和恢复在服务可用前完成。后台只处理已收据化的派生内容。
缺失派生目录期间，`PlanReferenceClosure` 仍从原 journal 追溯未退役图片。
自动保留期清理等待三类补齐完成；手动退役在此前返回 `503 history_index_pending`。
已有退役证明及清理恢复继续由所属 owner 核验。

已有目录正常读取；缺失目录返回 `history_index_pending`。详情只在可见期间重读未就绪资源，隐藏或卸载取消。
补齐失败输出有界异常类别并返回 `history_index_failed`，保留原记录和文件，界面提供诊断与重启提示。

## GUI 与首屏

根 `NexusPipeline.exe` 使用 WinExe，承载手动图形启动和显式命令。命令模式连接调用者终端并保留标准流和退出码。
手动快捷方式及安装后启动指向根入口，原 Launcher 与已登记自启路径继续可用。

读取展示偏好后，桌面映像保护和挂起启动与 Host 准入重叠；后端可连接后恢复桌面代码，握手期限从此时开始。
失败先停止并回收所属启动。桌面注册与进程族释放由[启动反馈](startup-feedback.md)和[进程拥有权](process-ownership.md)定义。
主窗口覆盖层展示真实阶段与单调累计时间；Host 与前端均就绪后移除。托盘语言刷新、外部图片和后台索引独立于首屏。

手动启动显示界面，自启服从保存偏好，维护重启沿用展示意图。启动中关闭窗口隐藏至托盘，恢复继续并保持隐藏。
轻量模式使用托盘反馈并按意图打开浏览器；失败显示原因、错误码、复制诊断与退出。

前端插件准备最多六路，保持输出顺序；会话、当前页和插件准备各有计时。
核心会话确认后采用五秒首屏等待预算，慢任务沿原 owner 继续。健康插件在导航、隐藏恢复和短暂重连时复用。
每插件批读声明入口与样式，共用一次安装消费及包树租约；入口至多 2 MiB、样式至多 16 个且每个 128 KiB，编码响应至多 6 MiB。
返回前仍校验成员、物理身份、摘要、单链接和调用授权。

## 历史按需访问

历史与摘要使用服务端条件、稳定游标和分页；详情报告、日志、图片按用户访问和视口加载。
页面缓存、目录窗口及媒体释放统一见[前端状态](frontend-state.md)。
组合历史的混合页筛选读放大仍是独立待办，见[当前状态](../status.md)，不作为已完成查询下推记录。

## 定向验收

普通启动核对完成历史内容零读取、当前恢复和未知格式拒绝；展示读取核对 WAL 提交可见、SQL 写入拒绝及原字节不变。
有界复用覆盖外部提交、文件替换、关闭释放及跨实例隔离。完整诊断继续拒绝旧历史损坏。
原生入口覆盖启动反馈、关闭后恢复继续、CLI 及当前任务实际触及的维护路径。
历史查询基准与完整 journal 诊断、整机首屏分别报告；测量字段与调用归因见[诊断](diagnostics.md)。
