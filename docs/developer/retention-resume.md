# 自动留存的中断续办

三个真实进程中断点已核实：留存事务提交后、初始 journal 落盘后、删除开始前。
旧 writer 全族停止并在新启动完成恢复后，原清理合法结束为 `NotExecuted`；
下一次普通留存 tick 不再选择已逻辑退役的内容，字节因此保留。
原终态不能改写为执行成功，也不能直接重放其删除授权。

用户已确认限定自动续办，边界如下：

- 尚未结束的原已受理批次先按原 operation/outbox 找回，不另受理相同批次。
- 对已合法 `NotExecuted` 的自动留存批次，只在原主体为宿主自动留存、
  当前留存设置仍使该运行过期、原冻结退役证明仍完整时，才受理一份新的有界清理授权。
- 新授权沿用现有 file-cleanup 计划、operation、journal、outbox 和执行器；
  原退役证明及原 `NotExecuted` 收据保持不可变。当前引用、对象身份、writer 停止和恢复状态逐项复核。
- 每 tick 最多续办一个批次；内容缺失无合法删除证明、未知副作用或隔离状态均停止并报告，不自动重放。
- 不改变留存天数，不把手工退役批次纳入自动续办，不建立第二份恢复或归档权威。

续办授权使用现有清理 operation、计划、journal 和 outbox，按原退役 operation 绑定宿主内部主体；
原退役证明及收据保持不变。完成时若内容已有当前引用，由既有执行器记录引用跳过。
该决定来自补充包 P1S-08 对 `NotExecuted` 后新授权策略的确认要求。
