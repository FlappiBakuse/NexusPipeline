# 后端业务保留与有限补修

旧版行为参考固定为 v0.17.6（`3fa803f3cb3ab59564bfad6fcf19c512dbfcd45d`）。
新协议、新目录、未知状态保全及中断后安全重试规则继续有效，不增加旧格式兼容层。
Host 0.18.0、SDK 0.1.0 和官方插件 0.5.0 的未发布目标版本保持不变。

## 当前补修范围与出口

| 优先级 | 产品行为 | 完成条件 |
|---|---|---|
| 高 | 独立运行并发 | 不冲突的已受理运行实际并行；同资源仍拒绝；取消、停止和恢复隔离不被旁路 |
| 高 | 长期恢复容量 | 已结束历史不永久耗尽新受理额度；活动工作和回滚仍有受保护余量；历史事实及未知恢复证据不被删除 |
| 高 | 历史保留天数 | 生产入口按保存值执行到期保留策略；保护活动、待恢复和通知引用；沿用现有精确清理 |
| 中高 | 自动更新 | 保留等待任务和未来五分钟计划窗口；启动检查先于正常调度；默认首次五秒及后续十二小时检查 |
| 中 | develop 同版本更新 | 同版本不同包摘要可刷新 develop，可信 stable 可替换同版本 develop；相同摘要不重装，不自动降级，stable 同版本不同字节仍拒绝 |
| 中 | 设置与通知 | 日志级别实际过滤宿主日志；通知按宿主语言呈现业务摘要，保留内部四维事实和原因码 |
| 中 | Storage 局部去重 | 日期不变不进入无效写事务；同一受保护操作内复用已验证读取；跨作用域及外部输入变化仍重新核验 |

每项在最小有效层验证可观察结果；不以字段保存往返或纯策略通过替代生产入口消费。
默认只补变更规则及必要集成边界；不自动运行全后端、全 Storage 或全部插件回归。
失败保留原始结果，修根因后只补受影响项；没有无条件重试、跳过或降低断言。

## 限定实施方式

复用现有生命周期、资源租约、SQL 事务、journal、清理和 runner。
不新增分布式服务、第二套恢复权威、归档数据库、通用缓存/分片/影响分析平台。
不为目录比例搬迁全仓，不重写 journal 格式，不按类数或行数追逐精简指标。
容量预留继续保护已受理工作的配置恢复、停止收据和回滚；不能靠提高读取上限解决长期增长。
writer/Job 身份、真实停止证明、未知字节隔离、文件归属、秘密及控制面权限检查保持有效。

## 实现与定向证据

上述已确认缺口已完成限定补修。独立运行按 inbox 容量并发消费，共享资源继续由原有资源准入裁决；全局恢复投影的执行临界区使用原有实例发布队列，原生进程不因此串行。运行天数在成功提交后记住已观察日期，同日及日期回退不再提交无效写事务。

完成历史与活动容量的分工及逐项校验见 [限定容量修复](recovery-capacity-remediation.md)。保留天数由生产后台维护消费，每分钟最多推进一条运行的一页内容，沿用既有精确清理 outbox；日志/图片退役后才隐藏到期历史，活动、恢复及待通知引用仍阻断退役。原始业务和恢复事实保留，`history_retired_at_utc_ticks` 只表示查询可见性，不授权删除证据。

自动更新在正常调度启动前处理已有下次启动请求，并在自动应用开启且具备发行信任时进行最多三十秒的新检查。新候选本次启动直接尝试交接，持久时机保留 NextStartup，因此本次交接前失败仍可在下一次启动处理；运行中自动应用遵守闲时和未来五分钟计划保护。默认首次检查五秒，后续十二小时；设置修订可触发重新检查。develop 刷新例外由已验证的新旧安装来源推导，HTTP 参数不能自授例外。

宿主日志动态消费保存级别，控制协议 stdout 独立保留；通知收据冻结生成时的语言，后续语言变化不使已排队消息失效，内部事实和原因码保留。
