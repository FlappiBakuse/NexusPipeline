## 维护规则

- 新条目必须先确认当前代码路径、回归测试和影响范围，再写入台账。
- 每个条目都要明确状态；修复、失效或被确认属于设计契约后立即移出本文件。
- 修复条目的历史说明进入 CHANGELOG 或 Git 历史，当前台账不保留版本完成清单和旧测试数字。
- 发现文档与代码/测试冲突时，先判断 intended contract；涉及产品行为的决定需要单独确认，不通过文档修改掩盖冲突。
