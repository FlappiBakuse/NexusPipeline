# 管理账号配置

> 本地候选操作说明；当前统一验证状态见[状态表](../status.md)。

## 先分清三份内容

| 内容 | 作用 |
|---|---|
| 脚本原来的配置 | 软件开始本次运行或编辑前，脚本目录中真实存在的内容 |
| 账号已保存配置 | 该账号与脚本绑定的配置，供后续运行使用 |
| 本次运行中的配置 | 当前脚本正在使用和更新的内容，可能含进度、计数器或任务状态 |

运行结束恢复脚本原现场，并不意味着丢弃账号已经确认保存的更新。同一次普通失败重试继续使用本次运行中的进度，也不等于必须把这些变化长期保存。

## 第一次与主动读取

如果绑定还没有保存配置，普通脚本首次运行会从已明确绑定的有效现场自动建立初始快照。已经有快照时不会因后续运行再次自动覆盖它。

“读取现有配置”用于主动把脚本当前配置读入这个账号。先确认账号、脚本和资源正确；读取不会启动脚本。结果待确认时查询原操作，不重新发起另一次读取。


## 编辑与取消

从账号绑定点击“编辑配置”。有已绑定编辑程序时，界面应直接说明将编辑哪个账号并打开对应程序；技术资源列表用于必要的高级处理，不应要求每次重新拼路径。

编辑完成后保存；放弃本次修改时取消。两者都可能需要等待编辑程序停止和原现场恢复。不要手工替换正在编辑的文件，或因窗口关闭而认为保存已完成。

专项修复先显示修改内容，再由你应用。诊断可能说明“当前配置不能运行”，同时提供用于消除该问题的合法修复；运行被阻止不应自动阻止这项修复。修复也不能越过受保护字段或影响另一账号。

## 运行中的进度与长期同步

普通失败重试应接续上一调用的有效活动配置。例如脚本已写入检查点 1，下一调用应从 1 继续，而不是回到本次运行最初的 0。关闭自动保存长期配置，也不应取消同一运行内的进度接续。

自动同步按现有初次检查与运行结束流程执行。运行较短不等于结束时必然不保存；是否保存仍取决于绑定策略及输出有效性。专项声明要求结束回写时，界面应显示实际有效约束。

本轮恢复的同步规则允许合法配置紧凑化；内容相同而字节变少不应单独导致拒绝。配置缺失、空内容、损坏，或目录文件数减少到已保存目录的一半及以下时，保留旧快照并说明原因。

同步失败需要可见诊断，但不能把失败说成已经保存成功。修复输入后再按明确操作处理，不通过反复运行来猜测配置是否入库。

## 草稿、秘密与未知结果

关闭普通编辑面板保留草稿；明确取消才放弃。查询、探测或预览不能顺带保存父表单。

密码、令牌等秘密有“保留”“设置”“清除”的独立语义。空输入不自动表示删除。不要把秘密粘贴到日志、普通备注或问题截图。

保存结果未知时，先检查原操作与当前修订；确认后再继续。程序意外退出后的恢复与普通失败重试不同，见[排障](troubleshooting.md)与[队列和日程](schedules.md)。
