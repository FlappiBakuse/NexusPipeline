# 备份、恢复与目录迁移

> 本页说明当前数据保全边界。0.17 与 0.18 的运行数据仍各自保存，不因本轮恢复业务逻辑而增加旧格式导入。

## 备份什么

保留完整运行目录，以及与它配套的应用版本、插件版本和必要安装说明。默认无参数入口使用应用目录下的 `runtime`；显式指定过运行目录时，以实际使用的位置为准。

不能只复制一个数据库文件而遗漏同目录伴随文件或其他运行资源。配置、历史证据、待恢复数据和引用内容共同组成一个实例；缺少其中一部分可能导致恢复被拒绝。

## 备份步骤

1. 在界面请求停止正在执行的任务，等待程序停止与配置恢复完成。
2. 正常退出 Host、桌面与所属任务进程；关闭管理窗口本身不代表服务已经退出。
3. 复制整个运行目录到独立备份位置，保留原目录；备份期间不重新启动写入。
4. 记录日期、应用版本、实例位置和备份是否在完全停止后生成。

如果存在无法确认的恢复状态，先保留现场和诊断，不为制作“干净备份”删除提示文件、锁或数据。此时的完整副本可用于排障，但不能声明已经完成正常恢复。

## 恢复和迁移

选择与备份相容的完整应用版本，在独立位置恢复整个目录，再显式使用该运行目录启动。不要把多个备份的文件拼成一个实例；也不要同时启动两个 Host 写同一份数据。

首次打开后先核对实例、账号、配置、历史与恢复状态，再启用日程。涉及秘密的恢复受本机与用户保护机制约束，复制文件不保证能在另一台机器或另一 Windows 用户下直接解密；按专用凭据入口重新配置必要秘密。

迁移应用目录前同样完全退出。快捷方式、自启和安装登记应由原维护入口处理，不只移动 exe 后留下指向旧目录的任务。

## 保留旧版

0.17→0.18 使用新目录、新实例。旧目录及原程序继续用于查看旧数据，不复制旧数据库、插件和运行模板进新实例。新版“首次自动建立配置快照”只针对已绑定的脚本配置，不是旧版运行数据库迁移。

## 卸载

卸载前检查数据保留选项并确认备份。应用文件可以重新取得；账号配置、运行证据和失败现场应由你明确决定何时移除。遇到占用或身份不匹配时先排查，不手工递归删除一个尚在使用的运行目录。
