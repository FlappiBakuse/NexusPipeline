# 队列、日程与重试

> 本地候选操作说明；当前统一验证状态见[状态表](../status.md)。

## 创建队列

在“计划与队列”选择“新建调度队列”，添加需要执行的脚本选择并保存顺序。账号绑定还应处于启用状态，且具有有效配置和目标。

next 支持同一队列重复选择同一个脚本；重复项按保存顺序作为各自的步骤处理。这是现有 next 能力，不把一个独立步骤误当成上一失败调用的继续。

保存后在“运行中心”选择该队列，先预览账号、步骤、资源与预算，再手动运行一次。确认结果后再加日程。

## 设置日程

为队列设置星期和时间，并确认保存的时区。跨时区浏览器操作时尤其要看清含义，不能仅根据本机任务栏时间猜测 Host 的日程。

日程在计划分钟请求运行；同一本地分钟不会因为重复检查或时钟回拨而另造一份运行。软件停机错过的分钟不自动补跑。资源冲突时沿原请求等待或显示阻塞原因，不新开另一个 Host 绕过独占。

“启动时运行”是单独的设置，不等同于补跑所有遗漏日程。取消、禁用或调整日程后检查保存结果；结果未知先查询原操作。

## 普通重试

脚本已经明确结束、停止与配置收尾可确认，而且未超过保存的调用次数和总时间预算时，普通失败可以再次调用当前绑定。已成功的前序绑定不因此全部重跑。

本轮恢复两项旧行为：下一调用接续上一调用的活动配置；已经配置业务判定规则而正常退出仍没有完成标记的适用普通执行，按失败和剩余额度处理。后者不会把所有未知结果一律变为可重试。

实际调用上限和总时间预算跨重试共用，等待或再次调用不会补发一套额度。取消、总预算耗尽、停止未确认或未知真实外部副作用时，不继续盲目调用。

## 意外退出后的恢复

Host 重启后先确认旧程序已经停止并恢复配置；恢复不代表自动把刚才的任务再执行一遍。不能确认上次副作用或剩余时间时，先保留记录并阻止自动续跑。

第三方签到、通知等请求即使本地超时，也可能已经到达对方。需要检查原结果；不要把“界面没收到成功”直接当作“对方没执行”。

## 完成动作

队列可以按已保存设置执行完成动作。停止和配置恢复必须先完成；受理一项结束动作不表示系统已经执行。关机、休眠或重启的倒计时应能查看和取消。

首次验证队列时使用不影响系统电源的设置。开发用例使用受控系统端口，不用真实关机来验证内部状态。远端操作不能借用本机权限触发原生动作。

结果、实际调用次数和恢复状态在[运行历史](history.md)中查看。
