# 按症状排障

> 当前已知缺口与实施状态见[状态表](../status.md)。先记录正在做的操作、软件版本、阶段和原操作身份，再做下表的最小检查。

| 症状 | 先检查 | 下一步 |
|---|---|---|
| 启动时长时间没界面 | 使用的是 GUI 新入口还是旧 Host；进度停在哪个阶段；数据量是否明显增长 | 保留阶段和错误；不要启动多个 Host 或清空 runtime |
| 大历史实例启动失败 | 是否命中已知大于 1 GiB 检查副本边界；磁盘空间和目录占用 | 使用对应修复候选验收；保持原数据库，不手工缩小或删除历史文件 |
| 选根目录后不能保存脚本 | 根目录、真实程序与专项插件是否正确；发现结果是否属于当前目录 | 老候选先点“读取脚本配置”；多候选明确选择，空结果不能猜选 |
| 提示需要配置 | 绑定是否已有保存快照、原配置是否有效 | 老候选使用“读取现有配置”；首次自动快照落地后检查失败原因，不以空配置代替 |
| 点击探测后编辑框意外关闭 | 是否发生非保存动作提交父草稿的已知问题 | 核对持久数据与草稿；提供操作顺序，不继续反复点击 |
| 提示资源不可用 | 失败操作对应的文件、目录或插件资源是否存在并可读取 | 修正该资源后重试对应操作；重新连接不能修复缺失文件 |
| 保存或开始运行结果未知 | 原操作是否已受理或完成 | 使用“查询操作状态”；保持原身份，不另造一次写入 |
| 登录窗口白屏或验证失败后关闭 | 官方来源、加载阶段、错误码、网络/代理、是否发生取消 | 保留最小诊断，在原会话重载；不要直接放开所有来源或反复输入凭据 |
| 账号摘要显示其他账号内容 | 链接与筛选是否保留该账号 | 显式选账号查看；这是本轮深链修复范围 |
| 大历史第一页很慢 | 当前筛选是否仍由旧前端逐页寻找组合记录 | 使用有服务端筛选的修复候选；不以“第一页无匹配”提前截断结果 |
| 取消后仍显示恢复中 | 程序是否真实结束，配置是否已恢复 | 等待或查看恢复原因，不删除锁、journal 或任务进程身份记录 |
| 插件升级或更新拒绝 | 版本、来源、完整包和信任是否匹配 | 使用正确资产；不修改摘要、清单或信任配置绕过验证 |

## 启动诊断

若需要命令行诊断，在终端进入实际应用目录，用原先的运行目录启动：

```powershell
.\NexusPipeline.exe serve --runtime-root 'D:\NexusData\runtime' --port saved
```

把示例路径换成你实际使用的目录。运行前确认没有另一个 Host 正在使用该实例。该命令用于保留启动诊断，不能用新空目录的成功掩盖原实例的问题。

## 提供什么材料

提供软件/插件版本、所用候选身份、实际操作步骤、预期与实际结果、错误码、关联 ID，以及受影响的账号或运行身份。界面版本号不足以说明精确源码；开发者还需要构建回执或提交信息。

日志只截取与问题相关的部分，隐藏密码、令牌和个人资料。支持包包含受限诊断，不能替代所有场景的完整日志，也不应声称它已经证明数据库或真实上游正确。

同一错误不做无条件重试。先确定失败属于输入、权限、资源、未知结果还是程序缺陷，再执行对应最小动作。只有确认修复影响了新的领域，才扩大验证范围。
