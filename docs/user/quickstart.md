# 第一次运行

> 本地候选操作说明；当前统一验证状态见[状态表](../status.md)。

## 操作前准备

准备脚本的真实安装目录、实际程序和该账号原本使用的配置。如果脚本需要游戏或模拟器，先确认对应程序或实例能够正常打开。专项脚本还需要它对应的官方插件处于可用状态。

第一次不必先建立复杂日程。先完成一个账号、一个绑定的一次运行，确认配置、目标与结果，再加入队列。

## 1. 在脚本库登记脚本

打开“脚本库”，选择“新建脚本实例”，填写名称并选择实际根目录。专项类型根据已安装插件选择；通用脚本填写实际可执行程序与必要参数。

选定专项根目录会自动读取发现结果。核对实际程序、配置、任务与目标；如果有多个候选，选择你使用的那一个。换目录后，旧目录的发现结果不能继续当作当前结果。


## 2. 创建账号并绑定脚本

打开“账号与配置”，添加账号，选择刚建立的脚本绑定。核对执行任务、游戏或模拟器目标、运行顺序与限制。创建账号只建立本地配置归属，不会自动登录第三方服务。

启用全局设置同步时，界面显示当前有效的全局值；需要独立设置时关闭相应同步，再编辑该账号自己的值。不要把被继承锁定的显示值当作可以直接覆盖的本地草稿。

## 3. 建立并检查配置

没有保存快照时，普通脚本首次运行会从已绑定、可验证的原配置建立初始快照。你也可以在运行前主动使用“读取现有配置”，检查保存的任务选择。来源不完整、被其他程序占用或无法核实时，先解决提示，不创建空白快照替代原配置。

需要编辑时从绑定的“编辑配置”进入，确认将打开的程序与账号。已有绑定应直接使用它的编辑入口；完成后保存，放弃则取消并等待恢复。[配置管理](configuration.md)解释运行中进度与长期保存的区别。


## 4. 预览本次运行

打开“运行中心”，选择“账号绑定”或对应脚本实例，点击“预览计划”。确认账号、任务、资源、目标与时间限制都符合本次意图。预览本身不执行任务，也不修改配置。

如果计划提示缺失配置或资源，返回对应绑定修复；预览变化后重新确认。不要通过切换到另一个实例来绕开当前占用或恢复提示。

## 5. 开始并观察

点击“开始运行”。“运行请求已受理”表示请求已接收；在“当前运行”查看实际状态和日志。请求取消后等待程序停止与配置恢复，不能只看按钮已返回就搬移目录。

如果保存或运行请求显示“结果待确认”，使用“查询操作状态”核实原操作。不要反复点开始来补偿一次网络超时。

## 6. 核对结果

从账号摘要或“运行历史”打开刚才的记录，确认该账号的业务结果、实际调用次数、日志与截图。失败时先查看原因；“进程结束”和“业务已完成”不是同一个状态。

这次运行符合预期后，再在“计划与队列”添加顺序和日程。相关步骤见[队列与日程](schedules.md)。
