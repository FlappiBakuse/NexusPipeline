# 用户指南

正式下载地址与已发布版本以 [Releases](https://github.com/FlappiBakuse/NexusPipeline/releases) 为准。本页说明当前源码实现的操作方式；隔离安装、旧版升级及真实游戏验收尚需对应环境验证。

## 安装和依赖

首次安装可选安装器或便携 ZIP。两者的初始应用文件来自同一份载荷：`NexusPipeline.exe`、`resources/desktop/`、`resources/payload-manifest.json`、`plugins/` 和 `README.md`。预装的 EmulatorSupport、LiveScreenshot 默认禁用，需要时再在插件页启用。安装器选择本地空目录；已登记且身份匹配的同一用户实例可选择原目录升级。它不会迁移或接管不明便携目录。便携包请解压到空目录，不要覆盖旧实例。

安装器提供英文和简体中文；首次安装按 Windows 用户界面语言选择并允许手动切换，升级默认沿用上次选择。`/LANG=en` 或 `/LANG=zh` 可明确指定语言。静默安装仍按显式语言、上次选择、系统语言的顺序决定提示语言。

从仓库首次安装 managed-code 插件且没有既有启用偏好时，安装事务完成后会记录启用，重启加载时生效。更新插件、显式禁用后重装及预装插件均保留原有偏好。安装请求返回需要重启时，插件还没有运行；实际加载状态以插件页为准。

普通模式下，双击根 NexusPipeline.exe 或选择托盘“打开管理页面”会打开或激活同一桌面窗口，窗口 X 仅隐藏，托盘退出才停止 Host。登录自启动通过 `service` 入口运行，设置“登录自启动时显示客户端”决定是否自动显示桌面。轻量模式只能在停止宿主后编辑 `config/settings.json` 中的 `"lightweightMode": true` 并重启启用；它运行后台服务、托盘和 Web UI，不启动 Electron。轻量模式的首次双击和登录启动均由 `openDesktopOnStartup` 决定是否自动打开默认浏览器；关闭时保持后台，再次双击或使用托盘仍可打开网页。服务或更新重启不重复打开网页。两种模式的远程访问均由 `allowRemoteAccess` 和现役认证控制；轻量模式可在网页中重启服务，MCP 仍由自身开关控制。网页设置页的「高级设置」卡片可单独保存「允许逐次配置修复」，每次修复仍需明确预览和应用。

程序需要 .NET Desktop Runtime 10 x64 和 ASP.NET Core Runtime 10 x64。安装器在缺少依赖时会逐项询问并从固定微软地址下载校验后的包。便携版保留 .NET 的缺运行时提示，两个准确下载按钮见可离线打开的 [[运行依赖说明](https://github.com/FlappiBakuse/NexusPipeline/blob/main/docs/user/README.md#安装和依赖)](../../frontend/public/help/runtime-prerequisites.html)。安装 .NET 依赖可能需要系统授权；取消后可重新运行安装器。

## 运行、取消和日志

在「调度中心」启动脚本或队列。点击取消后，当前运行停止接纳后续派发与重试；宿主请求停止本次拥有的进程，并在配置写入者退出后恢复配置。停止请求和进程退出可能不是同一时刻。若进程或配置恢复失败，保留现场并查看运行历史和诊断，不要手工清空 `data/` 中的恢复工作区。

当前日志按用户、队列运行和尝试分段。切换用户或重试后，请在当前段查看新的 stdout、stderr 或文件日志；历史段仍可在历史详情查看。启动就绪与无日志超时分别计时。程序窗口存在不表示 stdout 已有业务进展；无新增输出到达超时会结束尝试，并在清理确认后才评估安全重试。

## 结果和重试

「流程已结束 · 有未核验项」表示进程已结束，但至少一项任务缺少足够业务证据。它不表示任务成功。任务详情中的“已满足的跳过”需要插件给出本轮证据；仅凭配置勾选或通用完成横幅不会当作领取成功。

选择重试只针对插件和宿主共同证明独立、安全、未成功的项目。已成功项目、身份不清的项目以及关机、重启等高风险收尾动作不会被扩大重跑。若诊断提示动作会影响后续队列，请先检查队列与上游配置；宿主不会自动改写这些动作。

官方 OK 系列新发行在安装身份、入口和基础配置可确认时可受限运行：保留启动、取消、超时、历史，但旧版高级结果规则和选择重试关闭。更新或修复中、来源不可信、基础配置不适用时会显示具体阻断原因。受限运行后的正常进程退出仍显示未核验。

OK 启动器在任务结束后仍显示窗口，不单独判为失败。若其 `running` 标记遗留，但嵌入式 worker 已确认退出，Host 会提示并仅运行基础受限流程；检测到真实 worker 或无法读取进程身份时会阻断，Host 不替用户修改 `app.json`。

## 可选 MaaFramework 项目直驱

从商店单独安装并启用 MaaFrameworkDriver，重启后在脚本编辑器选择 `maa-framework` 和批准项目根。读取 PI 项目，选择 Controller、Resource、任务顺序与选项；先预览，再逐次授权并保存独立配置。绑定用户后加入现有队列，开始、取消和历史仍使用原有入口。原 MaaEnd／MaaStellaSora 专项不会自动转换。

Win32 显式选择匹配窗口，ADB 指定准确客户端和 serial。可只读导入已支持的 MXU 实例或 MaaPiCli 配置；源文件不会写入。受支持的 MXU 单个 PC 启动动作可在明确确认后映射到 Host 游戏启动设置。Agent／pretask 是项目代码，进程隔离不提供文件或网络沙箱；引擎完成仍可能显示未核验。框架范围与项目注意事项见 [官方 Plugins 仓库](https://github.com/FlappiBakuse/NexusPipeline-Plugins) 的 `docs/MAAFRAMEWORK_DRIVER.md`，驱动上架状态以商店实际目录为准。

## 配置修复

「允许配置修复」默认关闭。开启后，只对页面展示的具体修复建议先预览，再逐次点击应用；预览令牌绑定当前插件修复声明、用户、脚本、配置快照和文件字节。文件变化、插件能力变化或有运行/编辑冲突时需重新预览。当前八个专项按各自支持的配置提供游戏路径和完成动作修复；MaaEnd/MaaStellaSora 还支持关闭系统动作任务、补入首项启动游戏任务。OK 两款没有有限完成动作字段，不显示该项修复。每次应用先备份当前用户快照，不直接修改上游现场文件；页面会重读任务计划，并展示下一项可用修复。多个自定义启动程序无法确定归属或字段类型异常时，请手动核对。

## 升级、卸载与恢复

升级前退出程序并备份当前实例完整目录，包含程序、插件、`config/`、`data/`、`history/`、`logs/`、`.nxp/`，以及存在的 `user-assets/`、`.nxp-update/` 和 `.nxp-backup/`。更新页中的程序版本备份不能替代这份完整备份。

### 破坏性版本在新目录安装

v0.16.15 切换 .NET 10 与 Plugin API 2.0，并清理旧数据格式支持，必须手动安装到新的空目录并重新配置。v0.17.0 使用内嵌 Web、独立桌面客户端、Plugin API 2.1 和独立安装代际，需要单独手动升级；到达 v0.16.15 不表示可以自动跨越下一道屏障。v0.16.15 即使直接发现 v0.17.1，也会命中 v0.17.0 的 `desktop-shell-embedded-ui` 屏障，内置下载和应用保持关闭。下载以实际发布的资产为准。

1. 停止运行任务、退出配置编辑并关闭程序、旧网页、CLI 和 MCP 连接。若有未完成恢复，先在原版本处理，保留 journal、备份及其他现场。
2. 备份完整旧实例并原样保留旧目录。不要把旧目录整体复制到新版，也不要用便携包覆盖旧目录。
3. 从官方 Releases 取得目标版本，在新的空目录安装。v0.16.15 的运行环境为 Windows 11 x64、.NET 10 Desktop Runtime 和 ASP.NET Core Runtime；按目标版本安装包的依赖说明操作，无需 SDK、Node 或 npm。
4. 使用适配目标 Host 的官方插件，手动重建脚本、用户、队列及受影响配置，重新录入必要凭据。不要复制旧插件目录；原游戏和脚本目录保持原位，在新版中显式选择。
5. 验证任务、配置切换和通知后，再切换自启动。在旧实例中关闭原自启动设置；新旧实例逐次运行，不同时操作同一游戏配置或任务。

新版不转换、导入、移动或删除受影响的旧配置、外观及历史，不提供迁移工具。旧历史使用完整备份中的旧版查看；回退时也使用完整旧实例，不让旧程序读取新版数据。

同格式且未跨越屏障的普通更新仍可使用内置更新。此类更新如需手动替换，只替换 `NexusPipeline.exe`、`resources/desktop/`、`resources/payload-manifest.json` 和 `README.md`，保留用户目录及已有 `plugins/`。不明目录不能通过安装器就地接管。

### 卸载与恢复

卸载默认保留用户数据。只有在卸载开始前明确选择删除此实例用户数据后，才删除已确认归属的固定目录；发现链接或未解决恢复现场时拒绝删除，未知文件、外部游戏或脚本路径保留。.NET 依赖不会随本程序卸载。保留数据卸载后，同一用户可选择原路径重新安装，并明确确认重用保留数据；安装器不会据目录名接管其他数据。若安装、更新或卸载提示待恢复 journal、备份、文件锁或剩余文件，请保留现场并按 [恢复说明](../architecture/recovery.md)排查。

安装器可能在程序文件写入后报告“安装未完成”（退出码 12）。这时安装器会按已确认的事务结果补偿“应用和功能”登记与原生卸载器：未启动或确认回滚时恢复原版本；新版本已提交时保留新登记。若阶段尚无法确认，检查点和事务现场会保留，下一次可信安装会先尝试恢复；不要手动删除登记、`unins*`、`.nxp-update` 或 `.nxp-backup`，也不要将此目录当成空目录重新覆盖。

## 常见问题

**为何结束后不是成功？** 查看任务详情的未核验原因和本次日志段；上游没有独立确认时，宿主不能推断成功。

**为何新官方版本只有受限模式？** 高级判定需要该发行的配置与日志契约证据；基础启动可确认时仍可运行，结果保持未核验。

**为何安装器拒绝旧目录？** 它只接受符合该版本安装规则的目录，避免覆盖未知便携安装及用户数据。跨越破坏性版本必须选择新的空目录；同格式普通更新按上方说明处理。

**为何配置修复按钮不能应用？** 检查开关、预览令牌、当前文件是否变化，以及是否有运行或配置事务占用；确认后重新预览。

**能否用真实账号测试？** 本地自动化验收不包含真实账号、游戏、设备或机器人；这些验证应在独立授权的环境进行。

BAAH 的配置修复还可开启“是否输出日志到 /DATA/LOGS/ 目录”。修复保存到当前用户的软件设置快照，下次编辑或执行时由配置交换使用，不直接改正在运行的软件设置。
