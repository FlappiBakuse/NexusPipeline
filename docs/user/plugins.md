# 插件、网页登录与通知

本文说明当前插件操作。正式商店或更新来源是否可用，由所用包的发行配置决定；待验证范围见[当前状态](../status.md)。

## 选择与管理插件

进入“插件中心”，核对插件名称、用途、来源、版本、兼容性与启用状态，再安装或更新。专项脚本使用对应 adapter；一般插件提供签到、活动、壁纸、实时画面等能力。具体支持表和操作教程以 NexusPipeline-Plugins 仓库的用户文档及包内说明为准。

安装与启用是两步事实。已安装但停用时，能力不应继续接受新工作；卸载不会把既有运行历史改写为另一插件的结果。

新实例初始化时安装随包默认插件，完成后清理一次性材料。保留数据重装与应用更新沿用原插件状态；普通启动保留你的卸载和版本选择。已安装插件统一位于 `runtime/extensions`，应用根目录不再提供 `plugins` 文件夹。

优先通过插件中心安装或卸载。完整插件目录被手工移除时，启动或刷新插件中心会在相关任务释放资源后协调移除登记，保留账号、配置、绑定和历史。部分文件缺损时显示异常，可在本地插件详情卸载；父目录丢失、不可访问或被替换时先排查目录，软件保留原登记。手工复制的未登记目录不会执行。

签名、摘要或兼容性不匹配时检查正确包和来源，不手改 manifest 让安装继续。Test 候选中的信任只用于隔离验收，不代表正式商店信任已经配置。

## 专项配置

在账号绑定中查看发现结果与业务任务，再编辑或修复配置。插件提供的任务计划应能解释真实上游将执行什么；发现不到配置时，不把空列表当作“没有需要执行的任务”。

修复先预览、再明确应用。只更改已展示并授权的字段；其他账号、未知任务、注释和未选内容应保持原样。修复结果未知时，查询原操作。

## 网页登录

在插件凭据行选择“网页登录”，确认打开的是相应官方来源。窗口应显示加载阶段，并提供重载、取消和完成相关操作；页面加载失败时应能在原会话重试。

凭据格式满足后仍需要验证。验证成功才保存并关闭；失败应保留继续操作的上下文。不要把窗口自动关闭当作已经验证成功。

若窗口不加载，记录平台、加载阶段与错误码，见[排障](troubleshooting.md)。页面导航失败可在原窗口刷新；秘密的保留、设置和清除按专用入口处理。

## 通知

在“通知”选择通道、填写对应目标并保存专用凭据，再发送一次明确的测试。测试成功只证明这次目标可达；实际触发规则、去重和业务结果仍需核对。

通知已受理不等于外部已送达。状态未知时先核对原操作；关闭通知不会撤回已经发出的消息。运行结果和通知投递结果分别显示，不能把通知失败改写成脚本未执行。

## 设置中的插件分类

插件分类与宿主分类使用同一套展开规则：选择后打开并定位，再次选择可关闭，切换分类时保持阅读位置稳定。活动与壁纸设置即时生效，具体规则见各插件说明。
