# ADR-0169-001 · 执行事实、角色与恢复准入

状态：已采纳。适用于 Host v0.16.9 的后续执行扩展；原 taskProtocol 0.1.0 与旧历史保持可读。

## 事实层次

运行记录的机器事实分为四层：引擎状态、业务核验、自动化生命周期和恢复状态。引擎报告完成不自动成为业务已核验成功；游戏或启动器退出不自动成为引擎完成。恢复失败可与此前已核验的业务事实同时存在，展示时单独突出恢复问题。旧历史没有这些扩展字段时维持原字段与原字节，不推断出新的已核验事实。

受阻后继用现有可读状态 `skipped` 加稳定原因 `run.not_started_quarantined` 投影，并记录零次 attempt。它不算业务成功或已满足。人工取消的接受与正常终态提交受同一运行状态锁线性化；先接受取消则不得提交正常完成，正常终态已提交后不能追改。

## 进程与资源

Job 和进程查询返回 `complete`、`partial` 或 `unavailable`，同时携带原始 PID、已确权身份与未确权 PID。只有完整可信的必要角色静止可走恢复快路。查询失败或身份不可读绝不解释为空集合；先前确权身份不得因单次失败被遗忘。

角色与写入权限正交：一个纯伴随 `game_launcher` 可默认保留且不阻塞业务终态；若它同时写入受管配置，则仍是 `configuration_writer`，必须阻塞该资源恢复。`automation_worker`、`configuration_writer`、`game`、`game_launcher`、`observation_sidecar` 与 `unknown` 的实际身份按本轮启动契约和运行证据确权，不能只看进程名。无法确权的可能写入者保持受影响资源隔离，不全局误杀。

恢复隔离由现有恢复 journal 的版本化事实投影，同一准入协调域登记；先持久化、再转移租约、再扫描后继。资源交集包含配置路径、可写根、用户绑定、桌面输入和设备服务。独立候选按原队列顺序继续；受阻项仅记录一次且不自动回头补跑。整队人工取消在任何位置立即停止后续扫描。未解决恢复隔离抑制自动电源动作、宿主退出和自更新。

## Provider 边界

Plugin API 1.9 的 provider 为现有执行 owner 提供只读 Inspect、冻结 Prepare 和受控 Run；插件不得直接修改队列、历史或解锁恢复。原生事件进入独立结构化证据集合，由 Host 绑定会话与任务，旧日志证据仍按 taskProtocol 0.1.0 校验。没有授权、版本能力或精确资源范围时不启动 provider，也不退回空外部脚本路径。

本 ADR 描述兼容语义；具体 API、数据字段、原生调用和验证以同仓正式契约、源码与测试为准。
