## 功能和计量边界

同源原型完成 8 个视口会话、80 次页面/插件表面访问，包含导航晚响应和插件搜索。
原生检查覆盖 renderer 失败、Host 端口接管/重新连接、来源/证书拒绝、键盘与组合输入、
可访问性树、受控 HTTPS 登录、文件/目录选择、单实例恢复及实际 Windows 托盘图标。
隐藏保留同一窗口和 renderer；秘密编辑 DOM 清空，内存草稿可恢复，展示工作停止。
所有资源轮次完整记录进程身份、角色、最终 CPU 和退出；采集器自身单列。
GPU 内存与私有提交量单列，不与驻留 RAM 混为一个指标。

原生 HTTPS 的允许与拒绝采用真实 Host 授权和受控登录 fixture；
系统默认浏览器关联、正式提供商和安装升级的完整产品链路由 P1/P4 验证。
标题栏使用比较用原生外壳；生产标题栏、浏览器模式及完整 UI 在后续阶段验收。
物理输入法和读屏体验另保留人工感官核对，不把 CDP 组合输入当作物理设备实测。

Electron 44.9.0 使用 Chromium 152.0.7977.167；
WebView2 使用固定目录的 155.0.4283.62，两个引擎版本不同。
process-cold/profile-cold 已执行，保留缓存的 warm 对照和真正重启冷机为 NOT_RUN。
参考 UI/fixture 的结果不能代表全新 Host、五个新插件前端或 14 插件成品。
用户原先“CPU 超过 5%、内存超过 300MB”的观察缺乏同口径原始采样，仍未量化复现。

## 接入与分发

Host 负责实例、就绪、恢复、准入和统一关闭；桌面通过列举的类型化能力连接。
托盘与显示隐藏各有一个 owner，浏览器模式也复用 Host 生命周期。
生产桥接不包含原型探针、通用 eval、任意命令或旧协议 fallback。
秘密草稿归独立内存 owner；renderer 丢失后提示重新输入，未知操作不自动补发。

Electron 运行时随候选整体交付，锁定官方稳定版本、完整文件集合及摘要。
离线包须包含运行时和 Web 资源；缺失或摘要错误明确拒绝桌面启动。
更新通过已验证载荷和受控维护交接，确认完整 owned 家族停止后再替换。
运行时安全更新进入同一版本锁和验证流程，不在启动时静默下载另一版本。
桌面失败时保留可诊断状态，由用户明确选择浏览器模式。
Host 的生产管理员清单和隔离 Test Host 的 asInvoker 清单保持各自政策。
