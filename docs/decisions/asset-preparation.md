# 附件资产准备日志

JSON 导入需要先核验并准备全部不可变附件，再原子公开定义和资产引用。
文件准备与 SQLite 提交具有各自的持久化边界，使用专用 `assetPrepare` 类型进入共同 journal、outbox 和恢复隔离机制。
该类型补全资产准备这一文件操作；Automation 继续拥有定义和导入结果，Configuration 的文件机制负责证据及隔离。

冻结的 `nexus.asset.preparation-plan`/1 绑定实例、操作、journal、输入包摘要、目标目录身份、预览摘要和每个内容对象。
新内容只在本实例的规范内容寻址路径独占创建；既有对象必须匹配已冻结的摘要和身份。
目录、源文件及目标对象的身份和重解析点规则在相应适配器执行。
导入不会执行包中程序或任意命令。

正常阶段为 prepared → applying → applied → committed。
效果进入使用单次持久门禁；prepared 无效果取消仍要求完整证据、旧 writer 停止和独立 notExecuted 收据。
恢复不重做尚无完整收据的内容写入；无法证明的部分现场保全隔离。
内容收据全部闭合后，Automation 在一个 SQLite 事务内比较目标修订、公开完整定义/引用并保存操作结果。
进程中断后的文件事实、数据库投影和定义公开状态分别核验。

每个内容对象使用确定位置的独立 started/completed 收据，绑定实际 writer、计划、摘要、父目录及文件身份。
共同 journal 只记录阶段和已确权的收据目录，避免将全部文件收据重复写入每个 revision。
恢复先核验收据集合及 SQL outbox；缺失或未知收据不会触发内容重写。

`assetPrepare` 扩展初始六类操作的枚举，仍只接受逐类声明的合法阶段图和 typed plan。
未知类型、格式或收据继续只读拒绝。
新类型需要同步契约指纹、生成 SDK、消费者和恢复覆盖，产品版本维持 Host 0.18.0、SDK 0.1.0、插件 0.5.0。
P0 的六类日志证据保留其原始范围；资产准备由后续真实存储、进程中断及产品集成验证覆盖。
